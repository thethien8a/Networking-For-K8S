## Các bước thực hành / câu lệnh

1. **Khởi tạo hiện trường và khảo sát Control Plane:**
   - Lệnh: `kubectl -n nfk-26a-case1 get pods,svc,endpoints -o wide`
   - Quan sát: Pod `metadata-store` trạng thái `1/1 Running`, `Ready: true`. Service `metadata-store` có Endpoint `10.42.1.67:8080`.
2. **Khảo sát triệu chứng Data Plane:**
   - Lệnh: `kubectl -n nfk-26a-case1 exec data-ingest -- curl -v --connect-timeout 3 http://metadata-store`
   - Quan sát: DNS resolve ra IP `10.43.131.242`. Lỗi `Connection refused after 1 ms` (exit code 7).
3. **Thực hiện Control Test (bỏ qua Service VIP):**
   - Lệnh: `kubectl -n nfk-26a-case1 exec data-ingest -- curl -v --connect-timeout 3 http://10.42.1.67:8080`
   - Quan sát: `Connection refused after 0 ms`.
4. **Bắt quả tang Socket và giải mã bẫy Readiness Probe:**
   - Lệnh: `kubectl -n nfk-26a-case1 exec metadata-store -- netstat -tlpn`
   - Quan sát: `tcp 0 0 127.0.0.1:8080 0.0.0.0:* LISTEN 1/python3`.
   - Lệnh: `kubectl -n nfk-26a-case1 exec metadata-store -- python3 -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8080').status)"`
   - Quan sát: Trả về `200`.

## Review và tự giải thích

- 3 điều hiểu được:
  1. Phân biệt rạch ròi Control Plane Metadata (`kubectl get pod,svc,endpoints` xanh) với Data Plane Traffic (socket thật sự có lắng nghe trên interface nhận gói tin hay không).
  2. Bẫy Readiness Probe nội bộ: Probe chạy bằng `exec` hoặc gọi `localhost` sẽ thành công nếu tiến trình bind vào `127.0.0.1`, khiến Kubelet tưởng lầm Pod đã khỏe mạnh.
  3. Tư duy Active Probing và Control Test: Dùng `curl -v` bắt chữ ký thời gian (1ms Refused vs 3s Timeout), dùng gọi trực tiếp Pod IP để loại bỏ nghi ngờ tầng Service / Kube-proxy.
- 2 điều còn thắc mắc:
  1. Làm thế nào để viết Readiness Probe đúng chuẩn ngăn chặn lỗi bind `127.0.0.1` lọt vào production? (Ví dụ: dùng `httpGet` trỏ vào Pod IP hoặc cấu hình kiểm tra interface).
  2. Sự cố cross-node CNI (Case 2) sẽ có chữ ký khác biệt gì so với Case 1?
- 1 thử nghiệm tiếp theo:
  - Bài 26b — Fix tối thiểu cho Case 1, kiểm tra regression, và tiến hành triage + fix cho Case 2 & Case 3.
