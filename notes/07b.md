## Mục tiêu

- Tách bạch các nguyên nhân khiến hostname không hoạt động trong khi truy cập IP vẫn thông:
  1. Tên không tồn tại (`NXDOMAIN`) vs Resolver không phản hồi (`Timeout`).
  2. Bản ghi DNS trỏ nhầm vào IP cũ / IP chết (`Stale IP / IP mismatch`).
  3. Bẫy IPv6 (`AAAA`) trong môi trường mạng nội bộ IPv4.
  4. Bẫy Layer 7 Virtual Host / Ingress (`Host` header mismatch).
- Thực hành chọn phép đo kiểm đối chứng giữ biến ổn định (so sánh trực tiếp IP vs Hostname).
- Thực hiện sửa lỗi đúng chuẩn hạ tầng (sửa tại Source of Truth CoreDNS thay vì workaround file `/etc/hosts`).

## Các bước thực hành / câu lệnh

### 1. Baseline: So sánh truy cập IP trực tiếp và Hostname chuẩn
- Lệnh:
  ```bash
  docker exec nfk-07b-client curl -v http://10.250.75.10:8080/
  docker exec nfk-07b-client curl -v http://api.lab.internal:8080/
  ```
- Quan sát:
  - Lệnh 1 (IP): Không có bước phân giải tên, kết nối thẳng tới `10.250.75.10:8080`, gửi header `Host: 10.250.75.10:8080`, nhận `HTTP 200 OK`.
  - Lệnh 2 (Hostname): Xuất hiện log `Host api.lab.internal:8080 was resolved`, sau đó bắt tay TCP và gửi `Host: api.lab.internal:8080`, nhận `HTTP 200 OK`.

### 2. Đối chứng NXDOMAIN vs DNS Timeout
- Lệnh:
  ```bash
  docker exec nfk-07b-client curl -v http://notfound.lab.internal:8080/
  docker exec nfk-07b-client dig notfound.lab.internal
  docker exec nfk-07b-client dig @10.250.75.250 api.lab.internal
  ```
- Quan sát:
  - Tên không tồn tại: `dig` phản hồi ngay lập tức trong **1 msec** với `status: NXDOMAIN` và cờ SOA authority. `curl` ngắt tức thì báo `Could not resolve host`.
  - DNS Server chết (`.250`): Terminal bị treo 3–5 giây, sau đó báo `connection timed out; no servers could be reached`.

### 3. Điều tra Stale IP: "IP thông nhưng Hostname timeout"
- Lệnh:
  ```bash
  docker exec nfk-07b-client curl -v --connect-timeout 3 http://stale-host.lab.internal:8080/
  docker exec nfk-07b-client dig stale-host.lab.internal +short
  ```
- Quan sát:
  - `curl -v` phân giải tên thành công ra IP `10.250.75.99`, nhưng thất bại ở bước kết nối TCP (`Trying 10.250.75.99:8080... Connection timed out`).
  - `dig` trả về `10.250.75.99` thay vì `10.250.75.10`.
  - Kết luận: DNS hoạt động bình thường, nguyên nhân là bản ghi DNS chứa IP cũ / IP chết.

### 4. Bẫy Layer 7 Virtual Host: "IP 200 OK, Hostname 403 Forbidden"
- Lệnh:
  ```bash
  docker exec nfk-07b-client curl -v http://vhost-secret.lab.internal:8080/
  ```
- Quan sát:
  - Tên phân giải đúng `10.250.75.10`, kết nối TCP thành công 100%.
  - Server trả về `HTTP/1.0 403 Forbidden`. Khác biệt duy nhất nằm ở header `Host: vhost-secret.lab.internal:8080`.

### 5. Bẫy IPv6 (AAAA)
- Lệnh:
  ```bash
  docker exec nfk-07b-client curl -v --connect-timeout 3 http://ipv6bad.lab.internal:8080/
  ```
- Quan sát:
  - `curl` ưu tiên thử kết nối IPv6 trước (`Trying [2001:db8:dead:beef::1]:8080...`).
  - Gặp lỗi `Network unreachable`, `curl` mới fallback sang IPv4 `10.250.75.10`.

## Lỗi gặp phải và phân tích root cause (Break & Fix)

| Triệu chứng | Giả thuyết đồng nghiệp | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| `curl http://stale-host.lab.internal:8080/` bị timeout kết nối | DNS server không phân giải được tên miền | Dùng `curl -v` và `dig` đọc IP thực tế được phân giải | DNS phân giải tốt, nhưng bản ghi trỏ vào IP chết `10.250.75.99` (Stale IP). Không phải lỗi CNI hay lỗi DNS server. |

## Cách sửa và bằng chứng xác minh

- Phương án sửa:
  - Học viên phân tích chính xác vì sao không dùng `/etc/hosts` (do Pod trong Kubernetes là ephemeral, khi restart sẽ mất file hosts, và không giải quyết được cho các Pod khác trong cluster).
  - Khắc phục tận gốc: Cập nhật bản ghi `stale-host` trên CoreDNS từ `10.250.75.99` thành `10.250.75.10`.
- Bằng chứng xác minh:
  - `docker exec nfk-07b-client dig stale-host.lab.internal +short` $\rightarrow$ Trả về `10.250.75.10`.
  - `docker exec nfk-07b-client curl -v http://stale-host.lab.internal:8080/` $\rightarrow$ Trả về `HTTP/1.0 200 OK`, `Welcome to API service!`.

## Review và tự giải thích

- 3 điều hiểu được:
  1. Phân biệt rõ ràng lỗi phân giải tên (NXDOMAIN phản hồi ngay lập tức, Timeout mất 3–5s) với lỗi kết nối TCP (TCP connect timeout do IP chết).
  2. Bẫy Layer 7 Virtual Host: Gọi IP và gọi Hostname có thể đưa ra kết quả HTTP hoàn toàn khác nhau do header `Host`.
  3. Bẫy IPv6 (`AAAA`): Trình phân giải hệ thống ưu tiên thử IPv6 trước; nếu mạng không định tuyến IPv6, ứng dụng có thể bị treo hoặc chậm chạp trước khi fallback sang IPv4.
- 2 điều còn thắc mắc: (Được giải thích rõ ràng về cơ chế ephemeral của Pod và vì sao sửa file hosts là anti-pattern trong Kubernetes).
- 1 thử nghiệm tiếp theo: Bài 08a — HTTP Host header và TLS (SNI).
- Mức gợi ý cao nhất: Học viên tự đưa ra dự đoán và phân tích chính xác 100% các câu hỏi logic.
