# 05b — TCP handshake và connection state

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-25 23:05–23:26
- Thời lượng: 20 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (`LAPTOP-G35HS1Q6`), Docker Desktop Engine (`desktop-linux`), network cô lập `nfk-05b` (`10.250.55.0/24`). Học viên tự mở Git Bash / PowerShell chạy lệnh kết nối và quan sát gói tin giữa 2 container:
  - `nfk-05b-server` (`10.250.55.10`)
  - `nfk-05b-client` (`10.250.55.20`)
- Phiên bản và tài liệu đã đối chiếu: Ubuntu 24.04 LTS, iproute2 6.1.0, netcat-openbsd 1.226, tcpdump 4.99.4, Docker Engine 29.7.2.
- Phạm vi được phép thay đổi: Network và 2 container cô lập `nfk-05b`.

## Mục tiêu

- Nhận diện và phân tích cờ gói tin trong quy trình bắt tay 3 bước của TCP: `SYN` $\rightarrow$ `SYN-ACK` $\rightarrow$ `ACK`.
- Gắn kết số sequence/acknowledgment và chiều chuyển tiếp của cặp port (Source Port $\leftrightarrow$ Destination Port).
- So sánh đối chứng kết nối tới port mở (thành công `ESTABLISHED`) với port đóng (nhận cờ `RST`, văng lỗi `Connection refused`).

## Dự đoán trước lab

| Phép thử / Câu hỏi | Kết quả dự đoán | Phân tích & Thực tế đối chứng |
|---|---|---|
| Đầu nào gửi SYN, SYN-ACK đảo port như thế nào? | Client gửi SYN đầu tiên; SYN-ACK sẽ có cặp source/dest port là của Server về Client | **Chính xác**: Client thực hiện Active Open gửi SYN. Gói SYN-ACK từ Server đảo ngược 180 độ: Source Port = Server Port (9000), Dest Port = Client Port. |
| Gọi port đóng trên host reachable thì nhận được gì? | Bị connection refuse | **Chính xác**: Server không im lặng mà kernel lập tức phản hồi gói mang cờ RST-ACK, làm client báo lỗi `Connection refused`. |

## Các bước thực hành do học viên tự thực hiện

### 1. Bắt trọn 3 bước bắt tay TCP (SYN $\rightarrow$ SYN-ACK $\rightarrow$ ACK)
- Khởi chạy listener trên Server:
  ```powershell
  docker exec -d nfk-05b-server nc -lk 9000
  ```
- Bật tcpdump bắt luồng port 9000 trên Server:
  ```powershell
  docker exec -d nfk-05b-server sh -c "tcpdump -l -nn -i eth0 tcp port 9000 > /tmp/handshake.log 2>&1"
  ```
- Từ Client thực hiện kết nối:
  ```powershell
  docker exec nfk-05b-client nc -z -v 10.250.55.10 9000
  # Output: Connection to 10.250.55.10 9000 port [tcp/*] succeeded!
  ```
- Kết quả capture trên Server:
  ```text
  16:16:36.551631 IP 10.250.55.20.58540 > 10.250.55.10.9000: Flags [S], seq 3619424056, win 64240...
  16:16:36.551648 IP 10.250.55.10.9000 > 10.250.55.20.58540: Flags [S.], seq 3378309284, ack 3619424057, win 65160...
  16:16:36.551661 IP 10.250.55.20.58540 > 10.250.55.10.9000: Flags [.], ack 1, win 502...
  ```
  - `[S]`: SYN của Client.
  - `[S.]`: SYN-ACK của Server (port đảo ngược: 9000 $\rightarrow$ 58540; ack = 3619424056 + 1).
  - `[.]`: ACK của Client hoàn tất bắt tay.

### 2. Đối chứng khi Port Đóng (Cờ RST & Connection Refused)
- Bật tcpdump bắt port 9999 trên Server:
  ```powershell
  docker exec -d nfk-05b-server sh -c "tcpdump -l -nn -i eth0 tcp port 9999 > /tmp/closed_port.log 2>&1"
  ```
- Từ Client kết nối tới port đóng 9999:
  ```powershell
  docker exec nfk-05b-client nc -z -v 10.250.55.10 9999
  # Output: nc: connect to 10.250.55.10 port 9999 (tcp) failed: Connection refused
  ```
- Kết quả capture trên Server:
  ```text
  16:22:00.711881 IP 10.250.55.20.40672 > 10.250.55.10.9999: Flags [S], seq 3633159890...
  16:22:00.711894 IP 10.250.55.10.9999 > 10.250.55.20.40672: Flags [R.], seq 0, ack 3633159891, win 0...
  ```
  - Kernel Server phản hồi gói `Flags [R.]` (RST-ACK) chỉ trong **13 micro-giây**.
  - Không có bắt tay, kết nối bị từ chối tức thì.

## Bảng đối chứng tổng kết

| Tình huống | Cờ TCP trao đổi | Trạng thái phía Client | Thời gian phản hồi | Ý nghĩa chẩn đoán |
|---|---|---|---|---|
| **Port Mở (9000)** | `[S]` $\rightarrow$ `[S.]` $\rightarrow$ `[.]` | `succeeded` (`ESTABLISHED`) | Tức thì (~1ms) | Ứng dụng sẵn sàng nhận dữ liệu |
| **Port Đóng (9999)** | `[S]` $\rightarrow$ `[R.]` | `Connection refused` | Tức thì (13 µs) | Host/Mạng tốt 100%, lỗi tại tiến trình đích chưa bật |

## Rollback và Dọn dẹp (Do LLM tự động thực hiện)

- Đã xóa 2 container: `docker rm -f nfk-05b-server nfk-05b-client` (thành công).
- Đã xóa network: `docker network rm nfk-05b` (thành công).
- Xác minh sạch sẽ, không còn container hay network `nfk-05b` nào tồn đọng.

## Review và Tự giải thích

- **3 điều hiểu được:**
  1. TCP bắt tay 3 bước bằng `SYN` $\rightarrow$ `SYN-ACK` $\rightarrow$ `ACK` để đồng bộ sequence numbers trước khi truyền dữ liệu.
  2. Gói tin phản hồi từ Server luôn đảo chiều cặp Port: Source Port trở thành Server Port, Dest Port trở thành Ephemeral Port của Client.
  3. Lỗi `Connection refused` do chính kernel của máy đích gửi cờ `RST-ACK` về khi port không có tiến trình nào lắng nghe.
- **Câu áp dụng chẩn đoán Kubernetes:**
  - *Tình huống:* Pod báo lỗi `Connection refused` tức thì khi gọi Database Pod.
  - *Phân tích của học viên:*
    1. Gói tin đã đến được Pod đích (hạ tầng mạng thông suốt 100%, không phải do rớt gói hay firewall drop).
    2. Cần vào kiểm tra tiến trình bên trong Pod đích (kiểm tra container có crash không, app đã khởi động xong chưa, port cấu hình có đúng không), không phải lỗi hạ tầng mạng.
  - *Đánh giá:* Học viên nắm chắc tư duy troubleshooting mạng L4.
- **Mức hỗ trợ:** Không cần gợi ý giải pháp; học viên tự dự đoán và chạy thực hành thành thạo.
