## Các bước thực hành / câu lệnh

1. **Khởi tạo RBAC cho Spark trong namespace `nfk-27a`:**
   ```bash
   kubectl -n nfk-27a create serviceaccount spark
   kubectl -n nfk-27a create role spark-role --verb='*' --resource=pods,services,configmaps,persistentvolumeclaims
   kubectl -n nfk-27a create rolebinding spark-role-binding --role=spark-role --serviceaccount=nfk-27a:spark
   ```

2. **Kích hoạt Spark Job ở Cluster Mode với ràng buộc liên node:**
   ```bash
   kubectl -n nfk-27a run spark-submit-runner \
     --restart=Never \
     --image=spark:3.5.3 \
     --image-pull-policy=IfNotPresent \
     --overrides='{"spec":{"serviceAccountName":"spark"}}' \
     -- /opt/spark/bin/spark-submit \
     --master k8s://https://kubernetes.default.svc:443 \
     --deploy-mode cluster \
     --name spark-pi-baseline \
     --class org.apache.spark.examples.SparkPi \
     --conf spark.kubernetes.container.image=spark:3.5.3 \
     --conf spark.kubernetes.container.image.pullPolicy=IfNotPresent \
     --conf spark.kubernetes.authenticate.driver.serviceAccountName=spark \
     --conf spark.kubernetes.namespace=nfk-27a \
     --conf spark.executor.instances=1 \
     --conf spark.driver.memory=512m \
     --conf spark.executor.memory=512m \
     --conf spark.kubernetes.driver.node.selector.kubernetes.io/hostname=k3d-de-k3d-agent-0 \
     --conf spark.kubernetes.executor.node.selector.kubernetes.io/hostname=k3d-de-k3d-agent-1 \
     local:///opt/spark/examples/jars/spark-examples_2.12-3.5.3.jar 500
   ```

3. **Kiểm tra trạng thái Pods và Node Placement:**
   ```bash
   kubectl -n nfk-27a get pods,svc,endpointslices -o wide
   kubectl get nodes -o custom-columns='NAME:.metadata.name,POD-CIDR:.spec.podCIDR'
   ```

4. **Trích xuất bằng chứng mạng từ log Driver:**
   ```bash
   kubectl -n nfk-27a logs spark-pi-baseline-444abea1ec747b5d-driver | grep -E "(service '|SparkUI|NettyBlockTransferService|Registered executor|Registering block manager|broadcast_0|Pi is)"
   ```

## Bằng chứng

- **Driver Pod:** `spark-pi-baseline-444abea1ec747b5d-driver` trên Node `k3d-de-k3d-agent-0` (IP: `10.42.3.88`).
- **Executor Pod:** IP `10.42.1.76` thuộc PodCIDR `10.42.1.0/24` của Node `k3d-de-k3d-agent-1` (chứng minh cross-node).
- **Advertised Host của Driver:** `spark-pi-baseline-444abea1ec747b5d-driver-svc.nfk-27a.svc` (Headless Service, phân giải trực tiếp ra `10.42.3.88`).
- **Listeners mở trên Driver:**

  - `SparkUI`: TCP port `4040`
  - `NettyBlockTransferService` (BlockManager): TCP port `7079`

  - `Registering block manager 10.42.1.76:34365 with 117.0 MiB RAM`

## Review và tự giải thích

- **3 điều hiểu được:**
  1. Driver Headless Service (`clusterIP: None`) trả về trực tiếp Pod IP của Driver qua CoreDNS, bỏ qua hoàn toàn cơ chế Kube-proxy DNAT.
  2. Spark yêu cầu giao tiếp hai chiều: Executor gọi Driver RPC port `7078` để đăng ký, nhưng cả hai bên đều mở BlockManager port (`7079` trên Driver và port ngẫu nhiên trên Executor) để trao đổi data blocks.
  3. Khi Driver và Executor nằm trên 2 Node khác nhau, toàn bộ lưu lượng Spark được đóng gói qua CNI overlay (Flannel VXLAN UDP 8472).
- **2 điều cần lưu ý cho doanh nghiệp:**
  1. Trong môi trường có NetworkPolicy, nếu không cấu hình `spark.blockManager.port` cố định, Executor sẽ mở port ngẫu nhiên dẫn đến bị firewall/policy chặn đứng lúc Shuffle data (`FetchFailedException`).
  2. Địa chỉ quảng bá `spark.driver.host` phải đảm bảo phân giải và định tuyến được từ toàn bộ các Node trong cụm.
