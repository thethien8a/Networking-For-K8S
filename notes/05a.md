## Mục tiêu

- Phân biệt protocol, source/destination port, listen socket và connected socket.
- Đọc và phân tích 4-tuple của kết nối TCP; chứng minh nhiều client cùng kết nối tới một server port nhờ khác tuple.
- Kiểm chứng thực tế không gian port độc lập giữa TCP và UDP trên cùng một số hiệu port (`9000`).
- Phân biệt trạng thái socket TCP (`LISTEN`, `ESTABLISHED`) và UDP (`UNCONN`).

## Các bước thực hành do học viên tự thực hiện

### 1. Khởi tạo TCP Listener và đọc trạng thái ban đầu
- Học viên chạy lệnh mở server TCP:
  ```powershell
  docker exec -d nfk-05a-server nc -lk 9000
  ```
- Kiểm tra bảng socket TCP bằng `ss -tln`:
  ```text
  State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
  LISTEN 0      4096      127.0.0.11:38157      0.0.0.0:*          
  LISTEN 0      1            0.0.0.0:9000       0.0.0.0:*
  ```
  - `LISTEN`: Socket thụ động chờ kết nối ở port 9000.
  - `0.0.0.0:9000`: Wildcard bind (nghe trên mọi interface).
  - `0.0.0.0:*`: Chưa gắn kết với peer cụ thể.

### 2. Nối 2 Client đồng thời và quan sát Connected Sockets (4-tuple)
- Khởi chạy kết nối từ Client 1 và Client 2:
  ```powershell
  docker exec -d nfk-05a-client1 nc 10.250.50.10 9000
  docker exec -d nfk-05a-client2 nc 10.250.50.10 9000
  ```
- Kiểm tra toàn bộ socket TCP bằng `ss -tan` trên Server:
  ```text
  State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
  LISTEN 0      4096      127.0.0.11:38157      0.0.0.0:*           
  LISTEN 1      1            0.0.0.0:9000       0.0.0.0:*           
  ESTAB  0      0       10.250.50.10:9000  10.250.50.20:58100       
  ESTAB  0      0       10.250.50.10:9000  10.250.50.30:41492
  ```
  - Có 3 socket liên quan tới port 9000:
    - 1 socket `LISTEN` vẫn duy trì để đón kết nối mới.
    - 2 socket `ESTAB` đại diện cho 2 kết nối độc lập với Client 1 (port client: 58100) và Client 2 (port client: 41492).

### 3. Thử nghiệm UDP trên cùng Port 9000
- Khởi chạy UDP listener trên Server:
  ```powershell
  docker exec -d nfk-05a-server sh -c "nc -u -l -p 9000 > /tmp/udp.log"
  ```
- Kiểm tra socket UDP bằng `ss -uln`:
  ```text
  State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
  UNCONN 0      0            0.0.0.0:9000       0.0.0.0:*          
  UNCONN 0      0         127.0.0.11:59994      0.0.0.0:*
  ```
  - Cả TCP 9000 và UDP 9000 cùng mở song song không bị xung đột.
  - Trạng thái UDP là `UNCONN` (Unconnected), không có `LISTEN` hay `ESTABLISHED`.
- Bắn thông điệp UDP từ Client 1 sang Server:
  ```powershell
  docker exec nfk-05a-client1 sh -c "echo 'Hello UDP from Client 1' | nc -u -w1 10.250.50.10 9000"
  ```
- Kiểm chứng dữ liệu nhận được trên Server:
  - File `/tmp/udp.log` nhận trọn vẹn chuỗi: `Hello UDP from Client 1`.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Chạy `docker exec nfk-05a-server cat /tmp/udp.log` báo `cat: 'C:/Users/.../udp.log': No such file or directory` | Lỗi POSIX path conversion của Git Bash trên Windows | Bọc lệnh vào `sh -c` hoặc inspect file trực tiếp qua shell | Xác nhận Git Bash tự chuyển `/tmp/...` thành đường dẫn Windows; file `/tmp/udp.log` thực tế tồn tại trong container và chứa dữ liệu đầy đủ. |

## Rollback và Dọn dẹp (Do LLM tự động thực hiện)

- Đã xóa 3 container: `docker rm -f nfk-05a-server nfk-05a-client1 nfk-05a-client2` (thành công).
- Đã xóa network: `docker network rm nfk-05a` (thành công).

## Review và Tự giải thích

- **3 điều hiểu được:**
  1. Một kết nối TCP được định danh duy nhất bởi 4-tuple: `(Source IP, Source Port, Dest IP, Dest Port)`.
  2. Listen socket không bị biến mất hay chiếm dụng khi có client kết nối; nó tiếp tục nhận kết nối mới trong khi kernel sinh ra các connected socket (`ESTAB`) riêng biệt.
  3. TCP và UDP có không gian port độc lập. UDP là connectionless, trạng thái hiển thị là `UNCONN`, không có cơ chế handshake như TCP.
- **Câu áp dụng Spark / Data Engineering:**
  - *Tình huống 1:* 50 Spark Executors cùng nối về cổng 7077 của Spark Master có bị hết cổng không?
    - Học viên trả lời chính xác: Không, vì Master phân biệt bằng bộ 4-tuple `(source_ip, des_ip, source_port, des_port)`. Cổng 7077 là Listen Socket, mỗi Executor có IP riêng và Ephemeral Port riêng.
  - *Tình huống 2:* Gửi UDP tới cổng 7077 của Spark Master có nhận được không?
    - Học viên trả lời chính xác: Không, vì Spark Master mở TCP listener, trong khi TCP và UDP có không gian port riêng biệt.
- **Mức hỗ trợ:** Không cần gợi ý giải pháp; học viên tự dự đoán và trả lời đúng 100% các câu hỏi kiến trúc.
