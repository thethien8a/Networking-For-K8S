# 20b — Mini-incident DNS và Checkpoint 5 (CP5)

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-11-09 15:43
- Thời lượng: 40 phút
- Máy thực thi / OS / cluster context / namespace: macOS Darwin arm64 / k3d-de-k3d / namespace `nfk-20b`
- Phiên bản và tài liệu đã đối chiếu: K3s v1.33.6+k3s1, CoreDNS, `dnsPolicy` specifications (Kubernetes official docs)
- Phạm vi được phép thay đổi: Pod `analytics-client` trong namespace `nfk-20b`

## Mục tiêu

- Điều tra sự cố ẩn danh tầng DNS trong môi trường Kubernetes lab riêng.
- Vận dụng phân tầng chẩn đoán: dùng control test gọi trực tiếp ClusterIP để loại trừ Data Plane, đọc cấu hình resolver `/etc/resolv.conf`, phát hiện bẫy `dnsPolicy: Default`.
- Hoàn thành bộ 3 bản Incident Reports độc lập và nghiệm thu toàn diện **Cổng đánh giá Checkpoint 5 (CP5)**.

---

## Báo cáo sự cố tầng DNS (Incident Report Case C)

- Chi tiết báo cáo: [Incident Report Case C — DNS Resolution Failure do bẫy dnsPolicy: Default](incident-20b-dns.md)
- **Triệu chứng:** Client gọi `curl http://analytics-service` bị lỗi `curl: (6) Could not resolve host: analytics-service`.
- **Control Test:** Gọi trực tiếp bằng ClusterIP `curl http://10.43.190.138:80` trả về `HTTP/1.0 200 OK` ngay lập tức $\rightarrow$ Chứng minh 100% Data plane thông suốt, cô lập lỗi về DNS.
- **Phát hiện:** `/etc/resolv.conf` của Pod có `nameserver 192.168.155.1` (DNS của máy chủ Node hạ tầng) và thiếu hoàn toàn search domain của cụm. Pod spec cấu hình `dnsPolicy: Default` (kế thừa host) thay vì `ClusterFirst`.
- **Minimal Fix:** Recreate Pod với `dnsPolicy: ClusterFirst`. Sau khi sửa, `/etc/resolv.conf` nhận lại `10.43.0.10`, gọi tên miền Service thành công `HTTP/1.0 200 OK`.

## Nghiệm thu Cổng đánh giá Checkpoint 5 (CP5)

Căn cứ vào các tiêu chí tại [CHECKPOINTS.md](../CHECKPOINTS.md#cp5--sau-20b):

- [x] **Có đủ 3 incident reports riêng biệt:**
  - Case A: [incident-20a-case-a.md](incident-20a-case-a.md) (Selector mismatch).
  - Case B: [incident-20a-case-b.md](incident-20a-case-b.md) (TargetPort mismatch).
  - Case C: [incident-20b-dns.md](incident-20b-dns.md) (DNS Policy mismatch).
  - Không có trường hợp nào dùng giải pháp "restart hết tất cả" để tìm may mắn.
- [x] **Đầy đủ cấu trúc chuẩn kỹ sư:** Mỗi báo cáo đều có triệu chứng, baseline/topology, giả thuyết đối lập, bằng chứng đo lường khách quan, root cause, sửa đổi tối thiểu và post-fix checks.
- [x] **Phân biệt rạch ròi Metadata Service/EndpointSlice với kết nối thực tế:**
  - Case A chứng minh: EndpointSlice rỗng dẫn tới chủ động `REJECT` từ kube-proxy.
  - Case B chứng minh: EndpointSlice có IP và `Ready: true` **không đồng nghĩa** với việc kết nối thành công nếu targetPort lệch so với listener.
- [x] **Truy vết tầng DNS có Control Test chuẩn:**
  - Đọc cấu hình `/etc/resolv.conf`, đối chiếu nameserver của Host Node (`192.168.155.1`) với Service CoreDNS (`10.43.0.10`).
  - Dùng control test gọi trực tiếp ClusterIP để loại trừ Data Plane trước khi kết luận lỗi DNS.
- [x] **Fix không gây tác dụng phụ & dọn dẹp hoàn nguyên sạch sẽ:**
  - Mọi thao tác sửa đều là Minimal Fix đúng 1 biến.
  - Cả 3 namespace `nfk-20a-a`, `nfk-20a-b`, `nfk-20b` đều được LLM dọn dẹp sạch sẽ sau mỗi case.
