## Mục tiêu

- Phân biệt driver hostname/Service/port/path failure với application/resource error (OOM, Pod Pending, Exit code 137).
- Bóc tách sự cố kết nối liên node (cross-node) giữa Spark Driver và Executor khi bị NetworkPolicy chặn port.
- Chứng minh fix bằng cả kết nối executor→driver và kết quả job (`Pi is roughly ...`), lập báo cáo sự cố chuyên sâu tại [notes/incident-27b-spark.md](incident-27b-spark.md).

## Các bước thực hành / câu lệnh

1. **Khởi tạo kịch bản sự cố ẩn danh:**
   - Áp dụng NetworkPolicy `spark-driver-policy` chỉ mở Ingress port `4040/TCP` tới Pod `spark-role: driver`.
   - Submit job Spark Pi ràng buộc Driver trên `agent-0` và Executor trên `agent-1`.

2. **Điều tra hiện trường (Triage):**
   - Đọc status pods:
     ```bash
     kubectl -n nfk-27a get pods -o wide
     ```
     -> Thấy Driver `Error`, 5 Pods Executor liên tiếp `Error`, Runner `Completed`.
   - Đọc log Executor:
     ```bash
     kubectl -n nfk-27a logs spark-pi-8069b1a1ecace193-exec-1 --tail=30
     ```
     -> Thấy: `Failed to connect to spark-pi-incident-9621e8a1ecacd939-driver-svc.nfk-27a.svc/10.42.3.91:7078: Connection refused`.
   - Xác minh Driver listener:
     ```bash
     kubectl -n nfk-27a logs spark-pi-incident-9621e8a1ecacd939-driver | grep -E "sparkDriver|7078"
     ```
     -> Thấy: `INFO Utils: Successfully started service 'sparkDriver' on port 7078`.
   - Bắt quả tang NetworkPolicy chặn:
     ```bash
     kubectl -n nfk-27a describe networkpolicy spark-driver-policy
     ```
     -> Chỉ cho phép port 4040, chặn 7078 và 7079.

3. **Sửa tối thiểu (Minimal Fix):**
   - Bổ sung port 7078 và 7079 vào ingress spec của NetworkPolicy:
     ```bash
     cat << 'EOF' | kubectl apply -f -
     apiVersion: networking.k8s.io/v1
     kind: NetworkPolicy
     metadata:
       name: spark-driver-policy
       namespace: nfk-27a
     spec:
       podSelector:
         matchLabels:
           spark-role: driver
       policyTypes:
       - Ingress
       ingress:
       - ports:
         - protocol: TCP
           port: 4040
         - protocol: TCP
           port: 7078
         - protocol: TCP
           port: 7079
     EOF
     ```

4. **Kiểm chứng phục hồi (Post-fix verification):**
   - Xóa pods cũ: `kubectl -n nfk-27a delete pod --all`.
   - Submit lại job `spark-pi-fixed`.
   - Kết quả: Pod Driver chuyển sang `Completed`, tính thành công số Pi.

## Review và tự giải thích

- **3 điều hiểu được:**
  1. Phân biệt rõ rệt chữ ký DNS failure (unresolved host, chưa có TCP SYN) vs TCP Connection refused (đã resolve ra IP, nhận TCP RST từ firewall/closed port).
  2. Cách loại trừ ngay lỗi OOM (Exit code 137, Reason: OOMKilled) trước khi nhảy vào bắt gói mạng.
  3. Cấu trúc 2 luồng sống còn của Spark on K8s: RPC 7078 (đăng ký) và BlockManager 7079 (dữ liệu khối), cả hai đều phải được NetworkPolicy cho phép.
- **2 điều còn thắc mắc:**
  1. Nếu Executor dùng port ngẫu nhiên cho BlockManager thì làm sao cấu hình NetworkPolicy ingress cho Executor? (Giải pháp: dùng `--conf spark.blockManager.port=7079` để gán cứng port cho cả executor).
  2. Khi dùng Calico thay vì Kube-router, gói tin bị drop im lặng (timeout) hay bị reject? (Tùy cấu hình action DROP hay REJECT trong Felix).
- **1 thử nghiệm tiếp theo:** Bài 28a — Lập bản khảo sát Network Readiness Report toàn diện cho hệ thống 4 VM công ty.
- **Mức gợi ý:** Hint 1 (Định hướng bổ sung port 7079 cho BlockManager).
