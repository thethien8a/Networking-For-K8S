# 00 — Khởi động: biết mình học ở đâu và lưu gì

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-24 13:05
- Thời lượng: 15 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (x86_64) + WSL2 (`docker-desktop`)
- Phiên bản và tài liệu đã đối chiếu:
  - Windows WSL2: `wsl -l -v`
  - Docker Desktop: `docker.exe` (Docker version on PATH)
  - Python: `python.exe` 3.x trên PATH
  - Curl: `curl` trên PATH
- Phạm vi được phép thay đổi: Chỉ thay đổi trong lab cá nhân (WSL2 / local host / kind), tuyệt đối không fault injection trên hạ tầng công ty.

## Mục tiêu

- Phân biệt máy host, WSL2 Linux lab, node kind và VM công ty; xác định ranh giới an toàn khi thực hành.
- Đánh giá đầu vào ngắn để định vị phương pháp dạy.
- Thống nhất môi trường học và kiểm tra sự sẵn sàng cho bài 01a.

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| Khái niệm IP & Port | Xác định interface và socket/tiến trình | Học viên nắm rõ bản chất |
| `localhost` trong container | Không phải host ngoài mà là chính container | Container có network namespace riêng |
| DNS resolve thành công | Chưa đủ để kết nối | Cần port mở, app lắng nghe và không bị firewall chặn |

## Topology và địa chỉ IP

- Client / Host: Windows 11 (IP local loopback `127.0.0.1`)
- Môi trường Linux: WSL2 (hiện có `docker-desktop`, kế hoạch bổ sung `Ubuntu` distro cho bài 09a+)
- Môi trường K8s dự kiến: `kind` cluster chạy trên Docker Desktop / WSL2

## Các bước thực hành / câu lệnh

```powershell
# Kiểm tra WSL distros
rtk wsl -l -v

# Kiểm tra các công cụ CLI sẵn có trên máy
rtk powershell -Command "Get-Command docker, kubectl, kind, curl, python -ErrorAction SilentlyContinue"
```

## Bằng chứng

- `wsl -l -v` trả về: `docker-desktop` (Running, Version 2).
- `docker.exe`, `kubectl.exe`, `curl`, `python.exe` đã có sẵn trên PATH của máy.
- `kind` chưa được cài đặt.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Chưa có Ubuntu distro trong WSL2 | Máy mới cài Docker Desktop, chưa kích hoạt Ubuntu | `wsl -l -v` | Mới có `docker-desktop`, cần `wsl --install -d Ubuntu` khi tới bài 09 |

## Cách sửa và bằng chứng xác minh

- Cho bài 01a (HTTP request & endpoint): Sử dụng `python.exe -m http.server` và `curl` trên Windows host hoặc WSL2 đã sẵn sàng hoạt động.
- Cho bài 09a+ (Linux netns & firewall): Sẽ chuẩn bị Ubuntu distro trước khi bắt đầu bài 09a.

## Rollback / dọn dẹp / tài nguyên còn giữ

- Chưa thực hiện thay đổi cấu hình mạng nào. Không có tài nguyên cần rollback.

- 3 điều hiểu được:
  1. Ranh giới giữa máy host, container/WSL2 namespace, và VM công ty.
  2. Môi trường WSL2 Linux kernel thật là nơi thực hành Linux networking an toàn mà không ảnh hưởng host.
  3. Bài 01a chỉ cần HTTP client/server đơn giản, công cụ hiện tại đã đủ điều kiện bắt đầu.
- 2 điều còn thắc mắc: (sẽ theo dõi trong quá trình làm lab bài 01a)
