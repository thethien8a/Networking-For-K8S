# 01a — HTTP request và network endpoint

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-24 13:20
- Thời lượng: 25 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (MINGW64 / Git Bash)
- Phiên bản và tài liệu đã đối chiếu:
  - Python: `3.13.0`
  - curl: `8.16.0`
- Phạm vi được phép thay đổi: Localhost loopback port 8080 và 9999 trên máy lab cá nhân.

## Mục tiêu

- Chỉ ra client, server, process, IP và port trong một HTTP request.
- Phân biệt Network Endpoint (`IP:Port`) và cơ chế phân phối gói tin (Demultiplexing) của OS kernel.
- Kiểm chứng kết nối thành công vs kết nối thất bại ở tầng TCP (`Connection refused`).
- Hiểu tính chất loopback (`127.0.0.1` chạy trong bộ nhớ, không đi qua NIC vật lý).

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| Server chưa listen ở port 8080 | Request bị từ chối, không chạm tới mã nguồn ứng dụng | Kernel từ chối vì không có socket nào đăng ký nhận port đó |
| Gói tin tới `127.0.0.1` | Ban đầu chưa rõ | Sau giải thích: Gói tin loopback qua interface ảo `lo` trong RAM, không qua NIC vật lý |

## Topology và địa chỉ IP

```text
[ Client: curl (PID) ]  ---- (Ephemeral Port: 54020) ----+
                                                        |
                                                        v  (Loopback virtual interface 'lo' trong RAM)
                                                        |
[ Server: python (PID) ] <--- (Listening Port: 8080) ---+
```

## Các bước thực hành / câu lệnh

```bash
# Terminal 1: Chạy server
python -m http.server 8080

# Terminal 2: Gửi request tới port có listener
curl -v http://127.0.0.1:8080

# Terminal 2: Đối chứng với port không có listener
curl -v http://127.0.0.1:9999
```

## Bằng chứng

- **Request thành công tới port 8080:**
  ```text
  * Established connection to 127.0.0.1 (127.0.0.1 port 8080) from 127.0.0.1 port 54020 
  * using HTTP/1.x
  > GET / HTTP/1.1
  > Host: 127.0.0.1:8080
  > User-Agent: curl/8.16.0
  < HTTP/1.0 200 OK
  < Server: SimpleHTTP/0.6 Python/3.13.0
  ```
  Quan sát được: Endpoint máy chủ `127.0.0.1:8080`, Ephemeral port máy khách `54020`.

- **Đối chứng với port 9999 (không có listener):**
  ```text
  * Trying 127.0.0.1:9999...
  * connect to 127.0.0.1 port 9999 from 0.0.0.0 port 64620 failed: Connection refused
  * Failed to connect to 127.0.0.1 port 9999 after 2041 ms: Could not connect to server
  curl: (7) Failed to connect to 127.0.0.1 port 9999 after 2041 ms: Could not connect to server
  ```
  Kernel phản hồi TCP RST ngay tại tầng transport, không sinh ra HTTP status code nào.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| `Connection refused` ở port 9999 | Không có tiến trình lắng nghe ở cổng 9999 | `curl -v http://127.0.0.1:9999` | Không có kết nối TCP nào được tạo lập; Kernel trả cờ Reset |

## Cách sửa và bằng chứng xác minh

- Đây là bài kiểm chứng đối chứng có chủ đích để nhận diện lỗi `Connection refused`. Không cần sửa.

## Review và tự giải thích

- 3 điều hiểu được:
  1. Endpoint là sự kết hợp của IP (interface) và Port (socket của process).
  2. Gói tin phản hồi tìm về đúng client nhờ **Destination Port** (Ephemeral port do OS cấp) qua cơ chế Port Demultiplexing.
  3. Loopback `127.0.0.1` được xử lý ngay trong bộ nhớ/kernel, không đi qua NIC vật lý.
- 2 điều còn thắc mắc: Sẽ tìm hiểu ở bài 01b về sự khác nhau giữa bind `127.0.0.1`, bind IP interface thật, và wildcard `0.0.0.0`.
