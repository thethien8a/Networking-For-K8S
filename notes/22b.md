# 22b — TLS termination và lỗi hostname ở Ingress

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-11-10 16:47
- Thời lượng: 45 phút
- Máy thực thi / OS / cluster context / namespace:
  - macOS host: Darwin arm64 (Client curl)
  - k3d cluster: `k3d-de-k3d`, K3s v1.33.6+k3s1
  - Ingress Controller: Traefik v3.5.1
  - Namespace: `nfk-22a`
- Phiên bản và tài liệu đã đối chiếu:
  - Traefik Ingress Controller v3.5: https://doc.traefik.io/traefik/routing/providers/kubernetes-ingress/
  - Kubernetes Ingress TLS Spec: https://kubernetes.io/docs/concepts/services-networking/ingress/#tls
- Phạm vi được phép thay đổi: Namespace `nfk-22a`, Ingress `data-platform-ingress`, Ingress `trino-ingress`, TLS Secrets trong `nfk-22a`.

## Mục tiêu

- Chỉ ra TLS kết thúc ở đâu và protocol của từng đoạn sau đó (Client ↔ Ingress vs Ingress ↔ Pod backend).
- Bóc tách 3 tầng độc lập: Lỗi TCP/Network, Lỗi TLS Validation (SNI, CA Trust, Hostname Mismatch), và Lỗi HTTP L7 Routing / Backend.

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| HTTPS Client → Ingress thành công có bảo đảm Ingress → Backend là HTTPS? | Không | TLS termination kết thúc tại Ingress Controller; controller bóc gói tin và forward HTTP cleartext tới Pod backend |
| Truy cập HTTPS không truyền `--cacert` của Root CA nội bộ | Thất bại ở TLS Handshake | macOS trust store không có CA của lab, curl báo lỗi `SSL certificate problem: unable to get local issuer certificate` trước khi gửi HTTP |
| Dùng `-k` gọi domain không tồn tại trong Ingress rules | TLS thành công nhưng HTTP trả 404 | `-k` bypass xác thực cert, Traefik trả fallback cert rồi nhận HTTP request; không khớp rule nào nên trả 404 Not Found |

## Topology và địa chỉ IP

```text
[ Client (macOS) ]
       │
       │  🔒 HTTPS / TLS 1.3 (Port 443) - Traefik giải mã TLS
       ▼
[ Ingress Controller (Traefik on Node IP: 192.168.155.2:443) ]
       │
       │  🔓 HTTP bản rõ (Cleartext, Port 8080)
       ▼
[ Pod Backend: analytics-backend (10.42.1.41:8080) ]
```

## Các bước thực hành / câu lệnh

1. Sinh Root CA và Server Certificate cho `*.lab.local` có SAN (Subject Alternative Name) đầy đủ:
   ```bash
   openssl req -x509 -nodes -newkey rsa:2048 -keyout /tmp/nfk-tls/ca.key -out /tmp/nfk-tls/ca.crt -days 365 -subj "/CN=Lab-Root-CA"
   openssl req -new -nodes -newkey rsa:2048 -keyout /tmp/nfk-tls/server.key -out /tmp/nfk-tls/server.csr -subj "/CN=analytics.lab.local"
   openssl x509 -req -in /tmp/nfk-tls/server.csr -CA /tmp/nfk-tls/ca.crt -CAkey /tmp/nfk-tls/ca.key -CAcreateserial -out /tmp/nfk-tls/server.crt -days 365 -extfile /tmp/nfk-tls/ext.cnf
   ```
2. Tạo Secret TLS trong Kubernetes:
   ```bash
   kubectl create secret tls lab-wildcard-tls --cert=/tmp/nfk-tls/server.crt --key=/tmp/nfk-tls/server.key -n nfk-22a
   ```
3. Cập nhật Ingress `data-platform-ingress` với `spec.tls`:
   ```yaml
   spec:
     ingressClassName: traefik
     tls:
     - hosts:
       - analytics.lab.local
       - warehouse.lab.local
       - data.lab.local
       secretName: lab-wildcard-tls
   ```
4. Đo kiểm ma trận 3 tầng:
   - Đo 1: `curl -v --cacert /tmp/nfk-tls/ca.crt --resolve analytics.lab.local:443:192.168.155.2 https://analytics.lab.local/`
   - Đo 2: `curl -v --resolve analytics.lab.local:443:192.168.155.2 https://analytics.lab.local/`
   - Đo 3: `curl -k -v --resolve invalid.company.com:443:192.168.155.2 https://invalid.company.com/`

## Bằng chứng

- **Đo 1 (Hợp lệ):**
  - TLS Handshake: `subjectAltName: host "analytics.lab.local" matched cert's "analytics.lab.local"`, `issuer: CN=Lab-Root-CA`, `SSL certificate verify ok.`
  - HTTP Response: `HTTP/2 200`, `server: SimpleHTTP/0.6 Python/3.11.18`, Body: `[Analytics Engine] Path: / - Processing metrics...`.
- **Đo 2 (Untrusted CA):**
  - `CAfile: /etc/ssl/cert.pem`
  - `curl: (60) SSL certificate problem: unable to get local issuer certificate`.
  - Kết nối đóng ngay tại `Certificate (11)`, không có HTTP request nào được gửi đi.
- **Đo 3 (Bypass TLS, lỗi HTTP Routing):**
  - `-k` bỏ qua xác thực: `SSL certificate verify result: unable to get local issuer certificate (20), continuing anyway.`
  - Server trả về fallback cert: `CN=TRAEFIK DEFAULT CERT`.
  - Gửi HTTP request: `> Host: invalid.company.com`.
  - Traefik trả về: `< HTTP/2 404`, Body: `404 page not found`.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Gọi `https://trino.data.internal/` với `--cacert` bị `curl: (60) SSL certificate problem` | Lỗi mạng hoặc Ingress cấu hình sai secretName | Kiểm tra logs Traefik và Ingress spec | Traefik log: `Error configuring TLS error="secret nfk-22a/trino-tls-wrong does not exist"`. Traefik không tìm thấy Secret nên fallback về `CN=TRAEFIK DEFAULT CERT` |

## Cách sửa và bằng chứng xác minh

- Patch Ingress trỏ đúng secretName thật:
  ```bash
  kubectl patch ingress trino-ingress -n nfk-22a --type='json' -p='[{"op": "replace", "path": "/spec/tls/0/secretName", "value": "trino-tls-secret"}]'
  ```
- Kiểm chứng sau sửa:
  ```bash
  curl -v --cacert /tmp/nfk-tls/ca.crt --resolve trino.data.internal:443:192.168.155.2 https://trino.data.internal/
  ```
  Kết quả: `common name: trino.data.internal (matched)`, `SSL certificate verify ok`, `HTTP/2 200 OK`. Không cần dùng cờ `-k`.

## Rollback / dọn dẹp / tài nguyên còn giữ

- Xóa toàn bộ namespace `nfk-22a`: `kubectl delete namespace nfk-22a` (đã xóa sạch Ingress, Services, Pods, Secrets).
- Xóa thư mục certificate tạm: `rm -rf /tmp/nfk-tls`.
- Không giữ lại tài nguyên rác nào trên cluster.

## Review và tự giải thích

- 3 điều hiểu được:
  1. TLS Termination diễn ra tại Ingress Controller; đoạn Controller → Backend là HTTP bản rõ, không mặc định mã hóa.
  2. SNI (Server Name Indication) trong `Client Hello` là chìa khóa để Ingress Controller chọn đúng TLS Secret khi phục vụ nhiều domain trên cùng 1 IP:Port 443.
  3. Lỗi SSL/TLS Handshake xảy ra trước khi HTTP request được gửi đi; dùng cờ `-k` / `verify=False` là sai lầm nguy hiểm che giấu lỗi cấu hình hạ tầng K8s và phá bỏ an toàn bảo mật.
- 2 điều còn thắc mắc:
  1. Khi cần bảo mật End-to-End từ Client tới tận Pod backend (Zero Trust), cấu hình mTLS hoặc TLS passthrough trên Ingress Controller ra sao?
  2. Trong môi trường production lớn, công cụ như `cert-manager` kết hợp với Let's Encrypt / Vault tự động hóa việc xoay vòng (rotation) Secret TLS như thế nào?
- 1 thử nghiệm tiếp theo:
  - Khảo sát bài 23a về LoadBalancer bare-metal (MetalLB / Cloud Provider LB) để hiểu cách traffic bên ngoài đi vào Ingress Controller.
