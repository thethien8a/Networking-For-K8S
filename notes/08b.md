## Mục tiêu

- Theo dõi IP/port trước và sau chuyển địa chỉ, phân biệt rạch ròi SNAT (Source NAT) với DNAT (Destination NAT).
- Phân tích bảng 4-tuple (`Src IP:Port` -> `Dst IP:Port`) qua từng chặng và bẫy loopback bên trong container.
- Hiểu rõ bản chất: NAT không phải là Firewall; NAT không kiểm tra an ninh mà chỉ hoán đổi IP/port header.
- Hoàn thành toàn diện Cổng Đánh Giá Checkpoint 2 (CP2).

## Topology và địa chỉ IP

```
[Client trên Host]                           [Docker Gateway / NAT]                          [Web Container]
127.0.0.1:ephemeral                          172.17.0.1 (docker0)                            172.17.0.2:80
       |                                              |                                             |
       |--- (1) Gói tin ban đầu: -------------------->|                                             |
       |    Src: 127.0.0.1:ephemeral                  |                                             |
       |    Dst: 127.0.0.1:8080                       |--- (2) Sau khi DNAT & SNAT: --------------->|
       |                                              |    Src: 172.17.0.1 (SNAT: đổi nguồn)        |
       |                                              |    Dst: 172.17.0.2:80 (DNAT: đổi đích)      |
```

- Client Host: `127.0.0.1:ephemeral`
- Port Mapping trên Host: `0.0.0.0:8080` (hoặc `127.0.0.1:8080`)
- Docker Gateway bridge (`docker0`): `172.17.0.1`
- Container `nfk-08b-web`: IP `172.17.0.2`, Port `80` (Python `http.server`)

## Bằng chứng

### 1. Bảng 4-tuple thực tế đo được qua Port Mapping
- **Tại Client Host:** `127.0.0.1:ephemeral` -> `127.0.0.1:8080`
- **Tại Container Backend:** `172.17.0.1:ephemeral` -> `172.17.0.2:80`
- **Kết luận:**
  - **DNAT:** Đổi `127.0.0.1:8080` thành `172.17.0.2:80` (đổi đích để đưa traffic từ ngoài vào trong).
  - **SNAT:** Đổi nguồn thành `172.17.0.1` để khi backend gửi phản hồi về, gói tin đi ra `eth0` tới gateway `172.17.0.1` và được dịch ngược về cho client. Nếu không SNAT mà giữ nguyên `127.0.0.1`, container sẽ đẩy gói tin vào card `lo` nội bộ của chính nó và bị drop.

### 2. Kết quả đánh giá Cổng Checkpoint 2 (CP2)
Học viên đã trả lời chính xác toàn diện 4/4 tình huống đánh giá cổng CP2:
- **Tình huống 1 (TCP & Timing):**
  - Phân biệt chính xác `Connection refused` (2ms) do port đóng/không process listen -> Server gửi cờ RST/RST-ACK.
  - Phân biệt `Connection timed out` (30s) do Firewall DROP âm thầm -> Client kiên trì TCP retransmission cho tới khi hết hạn timeout.
- **Tình huống 2 (Connect Timeout vs Operation Timeout):**
  - Xác định chính xác lỗi dừng ở `* Trying...` là Connect Timeout (L4 TCP handshake thất bại).
  - Xác định chính xác lỗi dừng sau `> GET...` là Operation/Read Timeout (L7 ứng dụng backend / DB query bị nghẽn, L3/L4 đã thông suốt).
- **Tình huống 3 (Hostname: DNS vs TLS SNI vs HTTP Host):**
  - Trình bày rõ: DNS dùng hostname để phân giải ra IP đích.
  - TLS Handshake dùng hostname trong trường SNI (Server Name Indication) để server chọn cert, client đối chiếu với SAN (Subject Alternative Name) để tránh Hostname Mismatch.
  - HTTP Request dùng hostname trong `Host:` header để hỗ trợ Virtual Hosting trên Reverse Proxy / Ingress.
- **Tình huống 4 (DNS failure & NAT vs Firewall):**
  - Phân biệt NXDOMAIN (3ms - CoreDNS sống khỏe, không có bản ghi) vs DNS Timeout (10s - CoreDNS chết hoặc đứt kết nối).
  - Phản biện sắc bén: NAT không phải là Firewall; NAT chỉ tráo IP/port header và chuyển tiếp mù quáng mọi payload (kể cả exploit) vào container mà không chặn lọc an ninh.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết ban đầu | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Hiểu nhầm `localhost` tự resolve ra IP container | Host tự biết IP container | Kiểm tra packet và resolver | Host luôn resolve `localhost` ra `127.0.0.1`, DNAT trên kernel Host mới là bên đổi IP đích |
| Nhầm listen address `0.0.0.0` với client IP | Server startup message là access log | Đọc kỹ từng dòng log | `0.0.0.0` là listen wildcard; dòng access log phía dưới ghi rõ `172.17.0.1` |

## Review và tự giải thích

- 3 điều hiểu được:
  1. DNAT đổi Destination IP:Port (dùng cho Inbound như Docker port mapping, K8s Service NodePort/ClusterIP).
  2. SNAT đổi Source IP:Port (dùng cho Outbound như Pod ra Internet, hoặc tránh bẫy loopback container).
  3. NAT không phải là Firewall; NAT không kiểm tra payload mà chỉ hoán đổi địa chỉ gói tin.
- 2 điều đã làm sáng tỏ:
  1. Tại sao container thấy client là `172.17.0.1` thay vì `127.0.0.1`.
  2. Sự khác biệt rạch ròi giữa các tầng lỗi (L3/L4 TCP RST vs Firewall DROP; L6 TLS cert vs L7 Host header).
- 1 thử nghiệm tiếp theo: Bắt đầu Giai đoạn 3 (Linux Network Namespace, Veth pair, Linux Bridge từ bài 09a).
- Mức gợi ý cao nhất: Gợi ý mô hình thực tế Bác lễ tân và Bút xóa cho DNAT/SNAT.
