## Các bước thực hành & Bằng chứng thực tế

### 1. Tái hiện lỗi DNS Blackhole do Egress Isolation

Áp dụng policy chỉ mở port 80 tới backend, không khai báo egress cho DNS:
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: frontend-egress-to-backend-only
  namespace: nfk-24a
spec:
  podSelector:
    matchLabels:
      role: frontend
  policyTypes:
  - Egress
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: backend
    ports:
    - protocol: TCP
      port: 80
```

**Bằng chứng đo kiểm:**
- Khi curl bằng hostname:
  ```text
  * Resolving timed out after 3002 milliseconds
  curl: (28) Resolving timed out after 3002 milliseconds
  command terminated with exit code 28
  ```
- Khi curl bằng direct Pod IP (`10.42.1.61:80`):
  ```text
  Direct Pod IP: HTTP 200 | time: 0.006352s
  ```
-> Chứng minh phân tách rõ rệt: Đường truyền dữ liệu L4/L7 (TCP 80) hoàn toàn thông suốt, sự cố 100% nằm ở việc gói tin DNS Query (L4 UDP/TCP 53) bị Netfilter Egress của client chặn.

### 2. Cấu hình DNS Egress tối thiểu (Least-Privilege)

Bổ sung rule cho phép truy cập CoreDNS trong namespace `kube-system` trên cả 2 giao thức UDP và TCP port 53:
```yaml
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```

**Bằng chứng đo kiểm sau khi fix:**
- Frontend gọi Hostname thành công:
  ```text
  Frontend -> backend-svc:80 | HTTP 200 | time: 0.009224s
  ```
- Intruder gọi Hostname vẫn bị Backend Ingress chặn:
  ```text
  Intruder -> backend-svc:80 | HTTP 000 | ExitCode: 7
  command terminated with exit code 7
  Intruder blocked as expected
  ```
- Frontend gọi ra ngoài Internet (IP `1.1.1.1`):
  ```text
  command terminated with exit code 7
  External egress blocked as expected
  ```

## Phân tích chuyên sâu cho Data Engineering

1. **Tại sao phải mở cả UDP và TCP cho port 53?**
   - Hầu hết các DNS query thông thường sử dụng UDP để giảm overhead.
   - Tuy nhiên, khi DNS response vượt quá 512 bytes (EDNS0 buffer size) hoặc khi thực hiện DNS Zone Transfer, client bắt buộc phải fallback sang TCP port 53 (cờ `TC - Truncated` trong DNS header). Nếu chỉ mở UDP 53, các truy vấn trả về danh sách IP lớn (như headless Service của cụm Kafka, Cassandra, ElasticSearch) sẽ bị lỗi ngắt quãng khó chẩn đoán.
2. **Cạm bẫy Service VIP vs Pod IP trong Egress Policy:**
   - Trong Linux iptables/Netfilter, kube-proxy thực hiện DNAT từ Service ClusterIP (`10.43.214.39`) sang Pod IP (`10.42.1.61`) tại chain `PREROUTING` hoặc `OUTPUT`.
   - Controller như Kube-router giám sát Kubernetes API và tự động đưa Pod IP thực tế vào ipset (`KUBE-DST-...`). Gói tin sau khi DNAT sẽ khớp ipset của Pod đích và được cho qua.
3. **Chống Anti-pattern `allow-all egress`:**
   - Trong các cụm xử lý dữ liệu tài chính / Data Platform, mở `egress: [{}]` sẽ làm mất khả năng kiểm soát data exfiltration. Nếu một thư viện bên thứ 3 trong Spark job bị dính mã độc, nó có thể upload dữ liệu ra máy chủ C2 ngoài Internet.
