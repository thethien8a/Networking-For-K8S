## Các bước thực hành / câu lệnh

```bash
# 1. Tạo namespace
kubectl create namespace nfk-14a

# 2. Kiểm tra node PodCIDRs
kubectl get nodes -o custom-columns=NAME:.metadata.name,INTERNAL-IP:.status.addresses\[0\].address,POD-CIDR:.spec.podCIDR

# 3. Triển khai 2 Pod dùng nodeSelector gán vào k3d-de-k3d-agent-0
kubectl apply -f manifest.yaml

# 4. Kiểm tra placement và IP
kubectl get pods -n nfk-14a -o wide

# 5. Gọi trực tiếp Pod IP từ client sang server
kubectl exec -n nfk-14a client-same-node -- curl -s -I "http://10.42.3.18:8080" | head -n 1
```

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| zsh: no matches found với lệnh jsonpath/custom-columns có `[0]` | Shell zsh trên macOS hiểu nhầm ngoặc vuông `[0]` là glob pattern | Thoát ký tự `\[0\]` | Chạy thành công sau khi escape ký tự |

## Cách sửa và bằng chứng xác minh

## Review và tự giải thích

- 3 điều hiểu được:
  1. CNI IPAM per-node phân bổ một subnet `/24` cho từng Node; Pod sinh ra trên Node đó nhận IP thuộc subnet này.
  2. Kubernetes tuân thủ nguyên lý kết nối phẳng (IP-per-Pod): Các Pod có thể nói chuyện trực tiếp qua IP mà không cần NAT.
  3. CNI phụ trách tạo card mạng ảo và cấp IP, không phụ trách Service discovery (việc của CoreDNS/kube-proxy).
- 2 điều còn thắc mắc:
  1. Gói tin đi từ Pod client sang Pod server cùng Node sẽ đi qua những interface nào trên Node (có qua bridge không)?
  2. Tại sao lại cần interface `flannel.1` nếu cùng Node không đi qua nó?
- 1 thử nghiệm tiếp theo: Đo lường và bắt gói tin trên interface của Node ở bài 14b.
