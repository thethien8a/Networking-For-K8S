# 01b — Loopback, IP của máy và listen address

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-24 15:15
- Thời lượng: 25 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (x86_64), IP Wi-Fi `192.168.1.2`, Loopback `127.0.0.1`
- Phiên bản và tài liệu đã đối chiếu:
  - Python: `3.13.0`
  - curl: `8.16.0`
- Phạm vi được phép thay đổi: Port 8080 bind address trên máy lab cá nhân.

## Mục tiêu

- Phân biệt địa chỉ client gọi tới (Destination IP) với địa chỉ server đăng ký lắng nghe (Bind Address).
- Hiểu tính cục bộ của `localhost` / `127.0.0.1` (thuộc network namespace của từng máy/container riêng biệt).
- Kiểm chứng sự khác biệt giữa bind Loopback (`127.0.0.1`), bind IP interface thật (`192.168.1.2`), và Wildcard (`0.0.0.0`).
- Phân tích sự cố phổ biến khi container bind `127.0.0.1` khiến bên ngoài không truy cập được.

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| Server bind `127.0.0.1`, gọi bằng IP Wi-Fi `192.168.1.2` | Ban đầu dự đoán: thành công vì cùng một máy | Mâu thuẫn với thực tế: Kernel từ chối/treo request vì Destination IP không khớp Bind IP của Socket |
| Máy khác gọi `http://localhost:8080` | Gói tin tìm tới chính máy của người đó | `localhost` chỉ có ý nghĩa cục bộ trong network namespace của client |

## Topology và địa chỉ IP

```text
               +-----------------------------------------------------------+
               | Windows 11 Host                                           |
               |                                                           |
               |  +------------------+         +------------------------+  |
               |  | Loopback (lo)    |         | Wi-Fi Interface        |  |
               |  | IP: 127.0.0.1    |         | IP: 192.168.1.2        |  |
               |  +------------------+         +------------------------+  |
               |           |                                |              |
               +-----------|--------------------------------|--------------+
                           |                                |
  [ Bind 127.0.0.1 ]: Chỉ nhận traffic từ 'lo' <------------x-- Traffic từ Wi-Fi bị từ chối
  [ Bind 0.0.0.0   ]: Nhận traffic từ TẤT CẢ interfaces <---+-- Traffic từ Wi-Fi được chấp nhận
```

## Các bước thực hành / câu lệnh

```bash
# 1. Chạy server bind loopback
python -m http.server 8080 --bind 127.0.0.1

# 2. Gọi qua loopback (Thành công 200 OK)
curl -v http://127.0.0.1:8080

# 3. Gọi qua IP Wi-Fi (Thất bại / không ra kết quả)
curl -v http://192.168.1.2:8080

# 4. Đổi bind sang wildcard 0.0.0.0
python -m http.server 8080 --bind 0.0.0.0

# 5. Gọi lại qua IP Wi-Fi (Thành công 200 OK)
curl -v http://192.168.1.2:8080
```

## Bằng chứng

- **Khi bind `127.0.0.1`:** Cú gọi `curl -v http://192.168.1.2:8080` không nhận được phản hồi (treo timeout / bị kernel drop), dù IP `192.168.1.2` nằm trên chính máy đó.
- **Khi đổi bind `0.0.0.0`:** Cú gọi `curl -v http://192.168.1.2:8080` ngay lập tức trả về `HTTP/1.0 200 OK`.

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Gọi IP Wi-Fi khi server bind loopback bị treo/lỗi | Nghĩ rằng cùng máy thì IP nào cũng được | Thực nghiệm gọi `192.168.1.2` vs `127.0.0.1` | Kernel chỉ chuyển gói tin cho socket có IP khớp hoặc socket bind wildcard `0.0.0.0` |

## Cách sửa và bằng chứng xác minh

- Cấu hình server bind `0.0.0.0` để mở cho toàn bộ các network interface của máy.
- Bằng chứng: Request tới `192.168.1.2:8080` thành công trả về `200 OK`.

## Break & Fix thực tế

- **Case:** Container ứng dụng (Flask / FastAPI / Spark driver) chạy trong Kubernetes, dev test local bằng `localhost` thì được nhưng Pod khác hoặc Service không vào được.
- **Root cause:** Ứng dụng hardcode listen trên `127.0.0.1`. Khi đóng gói vào container, `127.0.0.1` chỉ là loopback của Pod đó. Gói tin từ bên ngoài đi vào qua interface mạng của Pod (`eth0`) có Destination IP là IP của Pod chứ không phải `127.0.0.1`, nên bị kernel trong Pod từ chối.
- **Giải pháp:** Cấu hình ứng dụng bind vào `0.0.0.0` (ví dụ: `uvicorn --host 0.0.0.0`).

## Rollback / dọn dẹp / tài nguyên còn giữ

- Tắt tiến trình `python -m http.server 8080` bằng `Ctrl + C`. Không còn listener nào treo trên port 8080.

## Review và tự giải thích

- 3 điều hiểu được:
  1. `Destination IP` của gói tin bắt buộc phải khớp với `Bind IP` của socket (hoặc socket phải bind `0.0.0.0`).
  2. `0.0.0.0` là địa chỉ cấu hình lắng nghe (Listen Address), không phải địa chỉ IP đích để client gọi tới.
  3. `localhost` chỉ có giá trị cục bộ trong network namespace của chính máy/container đang gọi.
