```bash

# 2. Đọc file cấu hình CNI và danh sách binaries
docker exec k3d-de-k3d-agent-0 cat /var/lib/rancher/k3s/agent/etc/cni/net.d/10-flannel.conflist
```

## Cây quyết định chẩn đoán mạng Kubernetes (Troubleshooting Decision Tree)

```
[ Bắt đầu sự cố mạng Pod ]
          │
          ▼
Kiểm tra Pod Status (`kubectl get pod -o wide`)
          │
          ├──> [ PENDING ] ──> Đọc `kubectl describe pod` (Events: Tầng SCHEDULER: thiếu CPU/Mem, nodeSelector, Taints).
          │
          ├──> [ CONTAINERCREATING ] ──> Đọc `kubectl describe pod` & Kubelet logs (Tầng RUNTIME/CNI SETUP: FailedCreatePodSandBox, hết IPAM, veth failed).
          │
          ├──> [ CRASHLOOPBACKOFF ] ──> Đọc `kubectl logs <pod>` (Tầng APPLICATION/L4: Xung đột port OSError 98, bind lỗi, panic).
          │
          └──> [ RUNNING ] (Đã có Pod IP)
                    │
                    ▼
          BỎ QUA `describe pod`! Chuyển ngay sang DATA PLANE:
          Đo bằng `curl -v <target-ip>:<port>`
                    │
                    ├──> [ CONNECTION REFUSED (0ms) ]
                    │       └──> Lỗi L4 Listener / Port Mismatch (ứng dụng chưa lắng nghe, bind nhầm `127.0.0.1`). L2/L3 CNI hoàn toàn bình thường!
                    │
                    ├──> [ CONNECTION TIMED OUT (2s - 30s) ]
                    │       └──> Lỗi L3 / Firewall / Tunnel (Packet DROP).
                    │               ├──> Ping Default Gateway (`10.42.x.1`):
                    │               │       ├──> 100% loss: Lỗi veth pair hoặc bridge `cni0` cục bộ.
                    │               │       └──> 0% loss: Pod Egress khỏe! Kiểm tra tiếp đường liên Node:
                    │               └──> Ping Pod khác Node:
                    │                       └──> 100% loss: Tường lửa chặn cổng VXLAN UDP 8472, hoặc NetworkPolicy chặn traffic.
                    │
                    └──> [ COULD NOT RESOLVE HOST ]
                            └──> Lỗi L7 DNS: Kiểm tra CoreDNS (`kube-system`), `ndots`, `/etc/resolv.conf`.
```
