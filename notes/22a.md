## Mục tiêu

- Phân biệt rõ bản chất giữa **Ingress Resource** (bản ghi metadata/rules tĩnh trong `etcd`) và **Ingress Controller** (tiến trình Reverse Proxy chạy ngầm, cụ thể là Traefik).
- Chứng minh cơ chế định tuyến tầng L7 (Application Layer):
  - **Host-based Routing:** Điều hướng lưu lượng dựa trên HTTP Header `Host` (`analytics.lab.local` vs `warehouse.lab.local`).
  - **Path-based Routing:** Điều hướng lưu lượng dựa trên URL Request URI (`data.lab.local/analytics` vs `data.lab.local/warehouse`).
- Khảo sát phản ứng của Ingress Controller trước các request không hợp lệ (Control Test với Host lạ $\rightarrow$ nhận `HTTP 404 Not Found`).
- Phân tích và xử lý sự cố Break & Fix: Bóc tách ranh giới kỹ thuật giữa `404 Not Found` (lỗi tầng Routing Rules) và `502 Bad Gateway` (lỗi tầng Upstream Backend / TargetPort Mismatch).
- Giữ lại môi trường namespace `nfk-22a` phục vụ trực tiếp cho bài thực hành **22b — TLS Termination**.

## Bảng so sánh Mental Model: 404 Not Found vs 502 Bad Gateway tại Ingress

| Tiêu chí | `HTTP 404 Not Found` | `HTTP 502 Bad Gateway` |
| :--- | :--- | :--- |
| **Giai đoạn xử lý** | **Tầng Routing Rules của Controller** | **Tầng Upstream Proxy / Kết nối Backend** |
| **Trạng thái Rule** | Controller **KHÔNG TÌM THẤY** bất kỳ rule nào khớp với cặp `(Host, Path)` | Controller **ĐÃ KHỚP RULE** thành công, tìm thấy Service và Pod Endpoints |
| **Hành vi mạng** | Controller tự sinh phản hồi 404 ngay lập tức; **không gửi bất kỳ gói tin nào vào cụm** | Controller chủ động mở kết nối TCP tới `<PodIP>:<targetPort>`, nhưng nhận về **TCP RST (`Connection refused`)** hoặc Timeout |
| **Log tại Pod backend**| **Hoàn toàn không có log** (request chưa từng chạm tới Pod) | **Không có log HTTP** (kết nối TCP bị kernel của Pod từ chối trước khi hình thành HTTP stream) |
| **Nguyên nhân phổ biến**| Sai Host header, sai Path prefix, thiếu IngressClass, quên apply Ingress | **Lệch `targetPort`**, ứng dụng backend crash/chết, Pod chưa sẵn sàng, NetworkPolicy chặn controller |

## Bằng chứng thực nghiệm

### 1. Ma trận định tuyến Host & Path qua Ingress Controller

| Phép thử | Lệnh thực thi | Kết quả HTTP | Nội dung phản hồi | Kết luận Data Path |
| :--- | :--- | :--- | :--- | :--- |
| **Host 1** | `curl -s -H "Host: analytics.lab.local" http://localhost:8085/` | `200 OK` | `[Analytics Engine] Path: / - Processing metrics...` | Traefik route đúng sang `analytics-svc` |
| **Host 2** | `curl -s -H "Host: warehouse.lab.local" http://localhost:8085/` | `200 OK` | `[Data Warehouse] Path: / - Querying records...` | Traefik route đúng sang `warehouse-svc` |
| **Path 1** | `curl -s -H "Host: data.lab.local" http://localhost:8085/analytics` | `200 OK` | `[Analytics Engine] Path: /analytics - Processing metrics...` | Traefik bẻ nhánh `/analytics` sang Analytics Pod |
| **Path 2** | `curl -s -H "Host: data.lab.local" http://localhost:8085/warehouse` | `200 OK` | `[Data Warehouse] Path: /warehouse - Querying records...` | Traefik bẻ nhánh `/warehouse` sang Warehouse Pod |
| **Host lạ** | `curl -i -s -H "Host: unknown.lab.local" http://localhost:8085/` | `404 Not Found` | `404 page not found` (19 bytes) | Traefik không khớp rule, tự trả về 404 |

### 2. Bóc tách chữ ký 404 của Traefik Default Backend
```http
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Tue, 10 Nov 2026 07:07:21 GMT
Content-Length: 19

404 page not found
```
- Phân tích: Header `X-Content-Type-Options: nosniff` và độ dài 19 bytes là định dạng mặc định từ engine Traefik (Go net/http), không phải do Python app trả về.

## Báo cáo Break & Fix: Bẫy TargetPort Mismatch và Lỗi 502 Bad Gateway

### 1. Hiện tượng
- Gọi `analytics.lab.local` bị trả về:
  ```http
  HTTP/1.1 502 Bad Gateway
  Date: Tue, 10 Nov 2026 07:24:32 GMT
  Content-Length: 11

  Bad Gateway
  ```
- Trong khi đó gọi `warehouse.lab.local` vẫn `200 OK`.

### 2. Phân tích nguyên nhân gốc rễ (Root Cause)
- Service `analytics-svc` bị cấu hình sai `targetPort: 9999` (trong khi container Python chỉ mở listener trên cổng 8080).
- EndpointSlice cập nhật endpoint thành `10.42.1.41:9999`.
- Traefik kết nối tới `10.42.1.41:9999` $\rightarrow$ Kernel của Pod trả về `TCP RST` do cổng 9999 không có tiến trình nào lắng nghe $\rightarrow$ Traefik ghi nhận upstream chết và trả về `502 Bad Gateway`.

### 3. Khắc phục tối thiểu (Minimal Fix) và Nghiệm thu
- Patch lại Service về đúng cổng `targetPort: 8080`:
  ```bash
  kubectl patch svc analytics-svc -n nfk-22a -p '{"spec":{"ports":[{"port":80,"targetPort":8080}]}}'
  ```
- Kết quả nghiệm thu:
  ```bash
  $ curl -i -s -H "Host: analytics.lab.local" http://localhost:8085/
  HTTP/1.1 200 OK
  [Analytics Engine] Path: / - Processing metrics...
  ```
  Kết nối phục hồi 200 OK ngay lập tức.

## Đúc kết bài học

1. **Ingress Resource là Metadata, Controller là Engine:** Khai báo Ingress trong YAML không có giá trị vận hành nếu cụm thiếu Ingress Controller (Traefik/Nginx) để thực thi.
2. **Kỹ thuật Host Header Mapping:** Khi chưa có DNS công cộng, client có thể dùng `-H "Host: <domain>"` để gửi gói tin tới IP của Ingress Controller mà vẫn kích hoạt đúng luật định tuyến L7.
3. **Phân biệt 404 vs 502:**
   - `404 Not Found`: Lỗi cấu hình Ingress Rule (không tìm thấy Host/Path).
   - `502 Bad Gateway`: Lỗi kết nối tới Upstream Backend (lệch `targetPort` hoặc Pod backend bị sập).
