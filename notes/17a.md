# 17a — Service, selector và EndpointSlice

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-11-07 14:05
- Thời lượng: 35 phút
- Máy thực thi / OS / cluster context / namespace: macOS (Host) -> cluster `k3d-de-k3d`, namespace `nfk-17a`
- Phiên bản: k3s v1.33.6+k3s1, containerd 2.1.5-k3s1.33, Linux kernel 7.2.12-orbstack
- Tài liệu đối chiếu: [Kubernetes Service](https://kubernetes.io/docs/concepts/services-networking/service/) · [EndpointSlices](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/)
- Phạm vi được phép thay đổi: Namespace riêng `nfk-17a`, Pods `be-1`, `be-2`, `client`, Service `my-data-svc`

## Mục tiêu

- Phân biệt bản chất giữa Pod IP (card mạng thực tế, ephemeral) và Service ClusterIP (Virtual IP, cố định).
- Hiểu mối quan hệ tam giác: `Service (selector)` -> `EndpointSlice Controller` -> `EndpointSlice (IP:Port, Ready)` -> `Pod (labels)`.
- Xác minh cơ chế chuyển tiếp và cân bằng tải của kube-proxy thông qua ClusterIP.

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| Service có selector nhưng không có Pod khớp | Trả về `Connection refused` (TCP RST) | Kube-proxy có rule REJECT chủ động khi Service rỗng endpoint, từ chối tức thì tại node, không timeout |
| Thay IP của Pod backend khi restart | Client không cần đổi cấu hình IP | Client chỉ gọi tới Virtual IP cố định (`ClusterIP`), EndpointSlice Controller tự cập nhật IP mới vào EndpointSlice |
| Khớp nhãn `selector: app=data-service` | Khớp cả 2 Pod dù có thêm nhãn `env=lab` | Selector hoạt động theo cơ chế tập con (subset match) |
| Cổng client gọi vs cổng backend nhận | Client gọi port 80, backend nhận port 8080 | Service expose `port: 80`, kernel DNAT sang `targetPort: 8080` của container |

## Topology và địa chỉ IP

```text
[ client ] (10.42.1.23 trên k3d-de-k3d-agent-1)
    │
    ▼ (gọi HTTP 10.43.204.13:80)
[ Kernel Netfilter / kube-proxy iptables ]
    │ (DNAT ngẫu nhiên sang 1 trong 2 endpoints)
    ├──────────────────────────────┐
    ▼                              ▼
[ be-1 ]                       [ be-2 ]
IP: 10.42.3.29:8080            IP: 10.42.1.22:8080
Node: k3d-de-k3d-agent-0       Node: k3d-de-k3d-agent-1
Label: app=data-service        Label: app=data-service
Ready: true                    Ready: true
```

- **Service:** `my-data-svc` (ClusterIP `10.43.204.13`, port `80/TCP`, selector `app=data-service`).
- **EndpointSlice:** `my-data-svc-w8l2l` gom 2 endpoints `10.42.3.29:8080` và `10.42.1.22:8080`.

1. Tạo namespace `nfk-17a` và 3 Pods (`be-1`, `be-2`, `client`):
   ```bash
   kubectl apply -f manifest-pods.yaml
   kubectl get pods -n nfk-17a -o wide --show-labels
   ```
2. Kiểm tra listener trực tiếp:
   ```bash
   kubectl exec -n nfk-17a client -- curl -s 10.42.3.29:8080
   kubectl exec -n nfk-17a client -- curl -s 10.42.1.22:8080
   ```
3. Tạo Service `my-data-svc` và kiểm tra đối tượng `EndpointSlice`:
   ```bash
   kubectl get svc,endpointslices -n nfk-17a
   kubectl describe endpointslice -n nfk-17a
   ```
4. Kiểm chứng luồng gọi qua ClusterIP từ `client`:
   ```bash
   kubectl exec -n nfk-17a client -- sh -c 'for i in $(seq 1 6); do curl -s 10.43.204.13:80; done'
   ```

## Review và tự giải thích

- **3 điều hiểu được:**
  1. Service ClusterIP là một địa chỉ IP ảo (VIP), không gắn lên interface vật lý hay veth nào; được kernel/kube-proxy hiện thực bằng rule DNAT.
  2. EndpointSlice là cầu nối quan trọng giữa Service và Pod: gom các Pod thỏa mãn cả 2 điều kiện (khớp `selector` và `Ready: true`).
  3. Khi Service không có backend endpoint, kube-proxy iptables chủ động phản hồi REJECT (TCP RST) gây `Connection refused`, không bị treo chờ Timeout.
- **2 điều còn thắc mắc:**
  1. Khi selector bị sai lệch 1 ký tự hoặc nhãn của Pod bị sửa đổi, EndpointSlice sẽ phản ứng trong bao lâu? (Sẽ kiểm chứng ở bài 17b).
  2. Kube-proxy cấu hình chi tiết các chain iptables nào để thực hiện cân bằng tải ngẫu nhiên? (Sẽ mổ xẻ ở bài 18a).
- **1 thử nghiệm tiếp theo:**
  - Thực hành bài [17b — Selector mismatch](../lesson/17b-selector-mismatch.md), cố tình sửa nhãn backend để quan sát EndpointSlice rỗng và bóc tách sự cố selector mismatch.
