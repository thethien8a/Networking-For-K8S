# 03b — Neighbor cache và MAC của gateway

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-25 15:10–15:35
- Thời lượng: 25 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (`LAPTOP-G35HS1Q6`), Docker Desktop Engine (`desktop-linux`), container `nfk-03b-a` và `nfk-03b-b` trên bridge network `nfk-03b`.
- Phiên bản và tài liệu đã đối chiếu: Ubuntu 24.04 LTS, iproute2 6.1.0, tcpdump 4.99.4, Docker Engine 29.7.2.
- Phạm vi được phép thay đổi: Chỉ thay đổi container và network cô lập `io.nfk.lesson=03b`.

## Mục tiêu

- So sánh cache còn dùng được (`REACHABLE`, `STALE`) với lần phải resolve lại neighbor.
- Phân biệt IP đích cuối (End-to-End L3) và MAC next hop (Hop-by-Hop L2) khi đích ở mạng khác.
- Làm mới một neighbor entry thử nghiệm đơn lẻ (`ip neigh del`), không flush toàn bộ bảng.
- Phân biệt lỗi L2 (`FAILED` neighbor / Host Unreachable) với các lỗi L4 (Connection Refused) hay L7 (DNS).

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán của học viên | Vì sao / giả định |
|---|---|---|
| Ping IP ngoài subnet `8.8.8.8` qua gateway `10.20.30.33` | Neighbor table chỉ xuất hiện MAC của Gateway `10.20.30.33` (Phương án B) | Host chỉ resolve ARP cho next hop cùng L2 link, không ARP ra Internet |
| Ping IP không tồn tại `10.20.30.40` cùng subnet | Trả về lỗi `100% packet loss`, trạng thái cache là `FAILED`, thuộc tầng `L2` | Không có host nào phản hồi ARP broadcast request |

## Topology và địa chỉ IP

```text
[nfk-03b-a] (10.20.30.50, MAC 86:6c:a7:a5:7b:d3)
     │
     ├── L2 bridge (10.20.30.32/27) ── [nfk-03b-b] (10.20.30.35, MAC 7a:b4:c2:31:c8:f3)
     │
     └── Default Gateway (10.20.30.33, MAC be:06:dd:77:d1:bf) ──> Internet / 8.8.8.8
```

- Bảng tổng hợp Đích cuối → Next Hop → MAC ở hop đầu:

| Đích cuối (L3 Destination) | Vị trí mạng | Next Hop (L3 Chặng kế tiếp) | MAC ở hop đầu (L2 Dest MAC) | Trạng thái quan sát |
|---|---|---|---|---|
| `10.20.30.35` (Container B) | Cùng subnet (`10.20.30.32/27`) | `10.20.30.35` (trực tiếp) | `7a:b4:c2:31:c8:f3` (MAC của B) | `REACHABLE` |
| `8.8.8.8` (Google DNS) | Ngoài subnet (Internet) | `10.20.30.33` (Default Gateway) | `be:06:dd:77:d1:bf` (MAC Gateway) | `STALE` |

## Các bước thực hành / câu lệnh

Do học viên tự chạy trực tiếp trên PowerShell host:

1. Kiểm tra bảng route và cache ban đầu:
   ```powershell
   docker exec nfk-03b-a ip route
   docker exec nfk-03b-a ip neigh
   ```
2. Ping ra ngoài subnet (`8.8.8.8`) và kiểm tra cache:
   ```powershell
   docker exec nfk-03b-a ping -c 2 8.8.8.8
   docker exec nfk-03b-a ip neigh
   ```
3. Ping cùng subnet (`10.20.30.35`) và kiểm tra cache:
   ```powershell
   docker exec nfk-03b-a ping -c 2 10.20.30.35
   docker exec nfk-03b-a ip neigh
   ```
4. Xóa đơn lẻ entry `10.20.30.35` không làm ảnh hưởng gateway:
   ```powershell
   docker exec nfk-03b-a ip neigh del 10.20.30.35 dev eth0
   docker exec nfk-03b-a ip neigh
   ```
5. Bắt gói tcpdump và kích hoạt ping lại sau khi xóa cache:
   - Cửa sổ 1: `docker exec -it nfk-03b-a tcpdump -n -e -i eth0 arp or icmp`
   - Cửa sổ 2: `docker exec nfk-03b-a ping -c 2 10.20.30.35`
6. Phép thử lỗi (Break & Fix): Ping IP không tồn tại `10.20.30.40`:
   ```powershell
   docker exec nfk-03b-a ping -c 2 -W 2 10.20.30.40
   docker exec nfk-03b-a ip neigh
   ```

## Bằng chứng

1. `ip route` ban đầu:
   ```text
   default via 10.20.30.33 dev eth0 
   10.20.30.32/27 dev eth0 proto kernel scope link src 10.20.30.50 
   ```
2. Sau khi ping `8.8.8.8`:
   ```text
   10.20.30.33 dev eth0 lladdr be:06:dd:77:d1:bf REACHABLE
   ```
   Xác nhận: Packet đi ra ngoài có Destination IP = `8.8.8.8` nhưng Destination MAC là MAC của Gateway `10.20.30.33`.
3. Sau khi ping `10.20.30.35`:
   ```text
   10.20.30.35 dev eth0 lladdr 7a:b4:c2:31:c8:f3 REACHABLE 
   10.20.30.33 dev eth0 lladdr be:06:dd:77:d1:bf STALE
   ```
4. Sau khi `ip neigh del 10.20.30.35 dev eth0`:
   ```text
   10.20.30.33 dev eth0 lladdr be:06:dd:77:d1:bf STALE
   ```
   Xác nhận: Xóa chính xác 1 entry độc lập mà không ảnh hưởng entry Gateway.
5. Capture sau khi xóa cache:
   ```text

   2 packets transmitted, 0 received, 100% packet loss
   Trạng thái neighbor: 10.20.30.40 dev eth0 FAILED
   ```

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| Ping `10.20.30.40` bị `100% packet loss` | Không tìm thấy thiết bị ở L2 do không có ai trả lời ARP request | Xem `ip neigh` trên máy nguồn | `ip neigh` ghi nhận `10.20.30.40 dev eth0 FAILED`; lỗi thuộc tầng L2 (Data Link) |

## Cách sửa và bằng chứng xác minh

- Invalidate cache đúng cách bằng `ip neigh del <ip> dev <iface>`.
- Đối chứng luồng bình thường: Sau khi đối phương trả lời ARP reply, kernel cập nhật ngay `REACHABLE` và frame ICMP được gửi thông suốt.

## Rollback / dọn dẹp / tài nguyên còn giữ

- LLM tự động thực hiện dọn dẹp theo quy định:
  - Xóa container: `docker rm -f nfk-03b-a nfk-03b-b` (Đã xác minh: 0 container).
  - Xóa network: `docker network rm nfk-03b` (Đã xác minh: 0 network).
  - Xóa image tạm: `docker image rm nfk-03b-tools:local` (Đã xác minh: xóa thành công).
- Không còn tài nguyên nợ rollback.

## Review và tự giải thích

- Điểm cốt lõi 1: L3 End Destination IP giữ nguyên xuyên suốt hành trình; L2 Destination MAC thay đổi theo từng hop (hop đầu là MAC của Gateway).
- Điểm cốt lõi 2: Neighbor cache chỉ quản lý thiết bị trên cùng L2 broadcast domain.
- Điểm cốt lõi 3: Trạng thái `STALE` là bình thường (chỉ là chưa có giao tiếp hai chiều gần đây, không có nghĩa mạng bị hỏng). `FAILED` mới là không tìm thấy MAC.
- Mức gợi ý cao nhất: Hint 1 (học viên tự trả lời đúng và tự chạy toàn bộ các bước kiểm chứng).
