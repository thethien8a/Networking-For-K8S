# 04a — Gateway, routing table và longest-prefix match

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-10-25 15:40–16:50
- Thời lượng: 30 phút
- Máy thực thi / OS / cluster context / namespace: Windows 11 host (`LAPTOP-G35HS1Q6`), Docker Desktop Engine (`desktop-linux`), container `nfk-04a` (`10.20.40.50/24`) trên bridge network `nfk-04a` (`10.20.40.0/24`). Học viên tự mở PowerShell chạy các lệnh quan sát.
- Phiên bản và tài liệu đã đối chiếu: Ubuntu 24.04 LTS, iproute2 6.1.0, Docker Engine 29.7.2.
- Phạm vi được phép thay đổi: Container và network cô lập `io.nfk.lesson=04a`.

## Mục tiêu

- Đọc connected route, default route, next hop và interface ra từ bảng routing của Linux kernel.
- Hiểu và chứng minh nguyên tắc Longest Prefix Match (LPM): prefix càng dài (càng cụ thể) thì độ ưu tiên càng cao.
- Dự đoán và đối chứng quyết định của kernel bằng lệnh `ip route get <IP>` với 5 địa chỉ đại diện: loopback, host on-link, gateway, off-link Internet, và chính IP của container.
- Phân biệt rõ: "có route trong bảng định tuyến" (điều kiện cần) khác với "kết nối/reachability thành công" (điều kiện đủ).

## Dự đoán trước lab

| Phép thử / Câu hỏi | Kết quả dự đoán của học viên | Phân tích & Thực tế đối chứng |
|---|---|---|
| Prefix `/24` vs `/25` khớp cùng đích | Dự đoán ban đầu: ưu tiên `/24` vì dải rộng hơn | Thực tế: Kernel dùng **Longest Prefix Match (LPM)**, ưu tiên `/25` vì có 25 bit mạng cố định, phạm vi hẹp và cụ thể hơn. Route `/0` (default) là ngắn nhất nên độ ưu tiên thấp nhất. |
| Có Default Route có đảm bảo thông mạng không? | Không đảm bảo, có thể có IP đặc biệt hoặc lỗi | Hoàn toàn chính xác: Bảng route chỉ là bản đồ chỉ đường nội bộ của kernel; kết nối có thành công hay không còn phụ thuộc Gateway, ARP L2, Firewall, Router trung gian và máy chủ đích. |

```text

        │                               └── Default Gateway (10.20.40.1) ──> Internet
```

## Các bước thực hành do học viên tự thực hiện trên PowerShell

1. **Đọc bảng routing table:**
   ```powershell
   docker exec nfk-04a ip route
   ```
   Output:
   ```text
   default via 10.20.40.1 dev eth0 
   10.20.40.0/24 dev eth0 proto kernel scope link src 10.20.40.50 
   ```
   - Học viên xác định chính xác: Dòng 2 là **connected route** (`scope link`), Dòng 1 là **default route** (`0.0.0.0/0`), Gateway là `10.20.40.1` qua interface `eth0`.

2. **Dự đoán và kiểm chứng 5 địa chỉ đích với `ip route get`:**

| Đích (Destination) | Phân loại | Học viên dự đoán | Kết quả thực tế từ `ip route get` | Khớp 100%? |
|---|---|---|---|---|
| `127.0.0.1` | Loopback | `dev lo`, no next-hop, `src 127.0.0.1` | `local 127.0.0.1 dev lo src 127.0.0.1 cache <local>` | Có |
| `10.20.40.100` | Cùng subnet on-link | `dev eth0`, không next-hop (trực tiếp), `src 10.20.40.50` | `10.20.40.100 dev eth0 src 10.20.40.50 cache` | Có |
| `10.20.40.1` | Gateway IP | `dev eth0`, trực tiếp (vì nằm trong subnet), `src 10.20.40.50` | `10.20.40.1 dev eth0 src 10.20.40.50 cache` | Có |
| `8.8.8.8` | Ngoài subnet (Internet) | `dev eth0`, via `10.20.40.1`, `src 10.20.40.50` | `8.8.8.8 via 10.20.40.1 dev eth0 src 10.20.40.50 cache` | Có |
| `10.20.40.50` | IP của chính mình | `dev lo` (loopback nội bộ), không next hop, `src 10.20.40.50` | `local 10.20.40.50 dev lo src 10.20.40.50 cache <local>` | Có |

3. **Mô phỏng Longest Prefix Match (LPM) với Prefix chồng lấn (Overlapping Prefixes):**
   - Cho bảng routing mô phỏng:
     - Route 1: `0.0.0.0/0 via 192.168.1.1 dev eth0`
     - Route 2: `10.0.0.0/8 via 192.168.1.254 dev eth0`
     - Route 3: `10.244.0.0/16 via 192.168.1.100 dev eth0`
     - Route 4: `10.244.3.0/24 via 192.168.1.103 dev eth0`
     - Route 5: `10.244.3.50/32 dev eth0 scope link`
     - Route 6: `192.168.1.0/24 dev eth0 scope link`
   - Học viên phân tích và chọn chính xác 5/5 route:
     1. `10.244.3.50` → Route 5 (`/32` cụ thể nhất)
     2. `10.244.3.88` → Route 4 (`/24`)
     3. `10.244.9.15` → Route 3 (`/16`)
     4. `10.50.1.1` → Route 2 (`/8`)
     5. `142.250.190.46` → Route 1 (`/0`)

## Rollback và Dọn dẹp (Do LLM tự động thực hiện)

- Đã xóa container `nfk-04a`: `docker rm -f nfk-04a` (thành công).
- Đã xóa network `nfk-04a`: `docker network rm nfk-04a` (thành công).
- Xác minh sạch sẽ qua CLI: `docker ps -a --filter "name=nfk-04a"` và `docker network ls --filter "name=nfk-04a"` không còn tài nguyên tồn đọng.

## Review và Tự giải thích

- **3 điều học được:**
  1. **Longest Prefix Match (LPM):** Linux kernel luôn ưu tiên route có tiền tố dài nhất (cụ thể nhất: `/32 > /24 > /16 > /8 > /0`). Default route (`0.0.0.0/0`) là route ngắn nhất, chỉ dùng khi không có route nào khác khớp.
  2. **Loopback cho chính mình:** Gói tin gửi tới chính IP của card mạng (`10.20.40.50`) được kernel xử lý qua interface `lo` nội bộ, không bị đẩy ra dây mạng vật lý hay bridge ảo bên ngoài.
  3. **Có route != Reachability:** `ip route get` chỉ cho biết quyết định chọn đường lý thuyết của kernel. Thực tế gói tin có đến được hay không phụ thuộc vào ARP phân giải MAC Gateway ở L2, Tường lửa (Firewall) ở L3/L4, và tính sẵn sàng của máy chủ đích.
