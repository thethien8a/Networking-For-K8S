# 11a — Router namespace nối hai subnet

- Ngày/giờ (Asia/Ho_Chi_Minh): 2026-11-03 16:55
- Thời lượng: 40 phút
- Máy thực thi / OS / cluster context / namespace: macOS Darwin arm64 (Apple Silicon), Docker runtime (OrbStack), container `nfk-11a-lab` (image `nfk-07b-tools:local`) với `--cap-add NET_ADMIN --cap-add SYS_ADMIN`.
- Phiên bản và tài liệu đã đối chiếu: Linux iproute2, sysctl `net.ipv4.ip_forward`, RFC 791 / RFC 1812 (Requirements for IP Routers).
- Phạm vi được phép thay đổi: Container lab riêng `nfk-11a-lab` và 3 network namespaces (`ns-a`, `ns-b`, `ns-router`). Tuyệt đối không đụng tới background cluster `k3d-de-k3d-*` hay network của host.

## Mục tiêu

- Tạo hai subnet riêng biệt qua một Router namespace với static routes.
- Kiểm chứng thực nghiệm quá trình định tuyến hai chiều (two-way routing) và cờ kernel `net.ipv4.ip_forward`.
- Bóc tách rạch ròi giữa Local Delivery (`INPUT`) và Transit Forwarding (`FORWARD`).

## Dự đoán trước lab

| Phép thử | Kết quả dự đoán | Vì sao / giả định |
|---|---|---|
| A có route tới B nhưng B chưa có route về A | Lỗi xảy ra ở bước phản hồi SYN-ACK | Gói SYN từ A đến được B, nhưng B không có route về subnet A nên kernel của B drop gói SYN-ACK. A bị handshake timeout. |
| Router tắt `ip_forward=0`, A ping tới chính IP Router vs xuyên qua Router | Ping Router OK, ping B thất bại | Gói gửi cho Router là Local Delivery (INPUT chain). Gói xuyên qua Router là Transit traffic (FORWARD chain), bị kernel drop nếu không bật forward. |

## Topology và địa chỉ IP

```
[ ns-a ] (Subnet 10.100.1.0/24)
  └─ veth-a: 10.100.1.2/24 (default via 10.100.1.1)
        │
        │ (veth pair 1)
        ▼
[ ns-router ] (Router namespace)
  ├─ veth-ra: 10.100.1.1/24 (Subnet 1)
  └─ veth-rb: 10.100.2.1/24 (Subnet 2)
  (net.ipv4.ip_forward = 1)
        ▲
        │ (veth pair 2)
        │
  ┌─ veth-b: 10.100.2.2/24 (default via 10.100.2.1)
[ ns-b ] (Subnet 10.100.2.0/24, HTTP Server port 8080)
```

## Các bước thực hành / câu lệnh

1. **Khởi tạo lab:**
   ```bash
   docker run -d --name nfk-11a-lab --cap-add NET_ADMIN --cap-add SYS_ADMIN nfk-07b-tools:local sleep infinity
   ```
2. **Tạo 3 namespaces và 2 veth pairs:**
   ```bash
   docker exec nfk-11a-lab ip netns add ns-a
   docker exec nfk-11a-lab ip netns add ns-b
   docker exec nfk-11a-lab ip netns add ns-router

   docker exec nfk-11a-lab ip link add veth-a type veth peer name veth-ra
   docker exec nfk-11a-lab ip link set veth-a netns ns-a
   docker exec nfk-11a-lab ip link set veth-ra netns ns-router

   docker exec nfk-11a-lab ip link add veth-b type veth peer name veth-rb
   docker exec nfk-11a-lab ip link set veth-b netns ns-b
   docker exec nfk-11a-lab ip link set veth-rb netns ns-router
   ```
3. **Cấu hình IP và interface:**
   ```bash
   docker exec nfk-11a-lab ip netns exec ns-a ip addr add 10.100.1.2/24 dev veth-a
   docker exec nfk-11a-lab ip netns exec ns-a ip link set veth-a up
   docker exec nfk-11a-lab ip netns exec ns-a ip link set lo up

   docker exec nfk-11a-lab ip netns exec ns-b ip addr add 10.100.2.2/24 dev veth-b
   docker exec nfk-11a-lab ip netns exec ns-b ip link set veth-b up
   docker exec nfk-11a-lab ip netns exec ns-b ip link set lo up

   docker exec nfk-11a-lab ip netns exec ns-router ip addr add 10.100.1.1/24 dev veth-ra
   docker exec nfk-11a-lab ip netns exec ns-router ip link set veth-ra up
   docker exec nfk-11a-lab ip netns exec ns-router ip addr add 10.100.2.1/24 dev veth-rb
   docker exec nfk-11a-lab ip netns exec ns-router ip link set veth-rb up
   docker exec nfk-11a-lab ip netns exec ns-router ip link set lo up
   ```
4. **Kiểm tra khi chưa có default route:**
   - `ip netns exec ns-a ping -c 2 10.100.1.1`: 0% loss (cùng subnet trực tiếp).
   - `ip netns exec ns-a ping -c 2 10.100.2.2`: `ping: sendto: Network unreachable` (socket error ngay lập tức do thiếu route).
5. **Thêm route trên `ns-a` nhưng chưa có route trên `ns-b`:**
   - `ip netns exec ns-a ip route add default via 10.100.1.1`
   - `ip netns exec ns-a ping -c 2 -W 1 10.100.2.2`: `2 packets transmitted, 0 received, 100% packet loss` (gói tin đã ra khỏi card mạng nhưng bị kẹt ở return path).
6. **Bật IP Forwarding và hoàn thiện route 2 chiều:**
   - `ip netns exec ns-b ip route add default via 10.100.2.1`
   - `ip netns exec ns-router sysctl -w net.ipv4.ip_forward=1`
   - Ping `10.100.2.2`: thành công 100%, `ttl=63` (bằng chứng qua Router L3 giảm 1 TTL).
7. **Khởi chạy HTTP và kiểm tra L7:**
   - Khởi chạy web server ở `ns-b`: `python3 -m http.server 8080`.
   - Gọi từ `ns-a`: `curl -s -I http://10.100.2.2:8080/` -> `HTTP/1.0 200 OK`.

## Bằng chứng

- **Bằng chứng Ping qua Router giảm TTL:**
  ```text
  PING 10.100.2.2 (10.100.2.2): 56 data bytes
  64 bytes from 10.100.2.2: seq=0 ttl=63 time=0.032 ms
  64 bytes from 10.100.2.2: seq=1 ttl=63 time=0.131 ms
  64 bytes from 10.100.2.2: seq=2 ttl=63 time=0.112 ms

  --- 10.100.2.2 ping statistics ---
  3 packets transmitted, 3 packets received, 0% packet loss
  round-trip min/avg/max = 0.032/0.091/0.131 ms
  ```
- **Bằng chứng Local Delivery vs Transit Forwarding khi `net.ipv4.ip_forward = 0`:**
  - Local Delivery tới Router (`10.100.1.1`):
    ```text
    64 bytes from 10.100.1.1: seq=0 ttl=64 time=0.076 ms
    2 packets transmitted, 2 packets received, 0% packet loss
    ```
  - Transit Forwarding tới `ns-b` (`10.100.2.2`):
    ```text
    PING 10.100.2.2 (10.100.2.2): 56 data bytes
    --- 10.100.2.2 ping statistics ---
    2 packets transmitted, 0 packets received, 100% packet loss
    ```
- **Bằng chứng HTTP 200 OK thành công xuyên subnet:**
  ```text
  HTTP/1.0 200 OK
  Server: SimpleHTTP/0.6 Python/3.12.15
  ```

## Lỗi gặp phải và phân tích root cause

| Triệu chứng | Giả thuyết | Phép kiểm tra phân biệt | Bằng chứng / kết luận |
|---|---|---|---|
| `sysctl: error setting key 'net.ipv4.ip_forward': Read-only file system` | Docker mặc định mount `/proc/sys` ở chế độ read-only | Chạy `mount \| grep proc` bên trong container | `/proc/sys` là `ro`. Fix: remount sang `rw` bằng `mount -o remount,rw /proc/sys` (khả thi nhờ `--cap-add SYS_ADMIN`). |
| Ping báo `sendto: Network unreachable` | `ns-a` chưa có tuyến đường nào tới dải `10.100.2.0/24` | Xem `ip route` trong `ns-a` | Bảng route chỉ có dải link-local `10.100.1.0/24`. Đã thêm `ip route add default via 10.100.1.1`. |

## Cách sửa và bằng chứng xác minh

- Cấu hình route hai chiều hoàn chỉnh (`default via 10.100.1.1` trên A, `default via 10.100.2.1` trên B).
- Bật `net.ipv4.ip_forward = 1` trên `ns-router`.
- Đối chứng: ping đạt 0% loss, TTL giảm còn 63, HTTP request nhận `HTTP/1.0 200 OK`.

## Review và tự giải thích

- 3 điều hiểu được:
  1. Router Layer 3 làm nhiệm vụ kết nối các subnet khác nhau bằng cách bóc tách Ethernet MAC cũ, tra routing table, bọc Ethernet MAC mới của hop tiếp theo và giảm TTL đi 1.
  2. Định tuyến là bài toán 2 chiều (two-way): Nếu A có route sang B nhưng B thiếu route về A, kết nối TCP/HTTP vẫn chết (SYN tới được nhưng SYN-ACK bị drop tại B).
  3. `net.ipv4.ip_forward` là cờ kernel quyết định transit traffic (FORWARD chain). Gói tin gửi cho chính IP Router thì `ip_forward=0` vẫn nhận bình thường (INPUT chain).
- 2 điều còn thắc mắc:
  1. Khi một router có nhiều card mạng hoặc nhiều đường về, kernel quyết định chọn card mạng nào để forward gói tin về?
  2. Nếu bật conntrack hoặc firewall (iptables), luồng return path bị lệch (asymmetric routing) sẽ bị ảnh hưởng như thế nào?
- 1 thử nghiệm tiếp theo: Bắt gói bằng `tcpdump` ở cả 2 cổng của Router trong bài 11b để nhìn thấy gói SYN và SYN-ACK bị drop ở đâu khi có sự cố.
- Câu áp dụng sang tình huống khác và câu trả lời:
  - *Tình huống:* Kubernetes Pod trên Node 1 ping tới IP vật lý của Node 2 thì được, nhưng ping tới IP Pod trên Node 2 thì 100% loss.
  - *Nguyên nhân:* Node 2 nhận ping vào IP vật lý là Local Delivery (vẫn phản hồi dù `ip_forward=0`). Nhưng chuyển tiếp gói tin từ card vật lý vào veth của Pod là Transit Forwarding. Kiểm tra ngay `sysctl net.ipv4.ip_forward` trên Node 2.
- Mức gợi ý cao nhất / có xem lời giải không: Tự làm, LLM chỉ hỗ trợ remount `/proc/sys` để set sysctl do sandbox của Docker.
